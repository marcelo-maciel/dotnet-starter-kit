# Module: PAF

PAF V2 queue management: the totem emits a ficha, the guiche calls it, the panel shows it. Module `Order = 900`, schema `paf`, `PafDbContext`.

## Rules

- **Domain language is Portuguese without accents** in identifiers (`Ficha`, `Fila`, `Guiche`, `Atendimento`, `Unidade`). Infrastructure (DbContext, initializer, module, endpoints plumbing) stays in English. See ADR 0004.
- **`Unidade` is a PAF entity**, not a kit concept. Every operational table carries `UnidadeId`. See ADR 0002.
- **Unit scope is a NAMED global query filter**, registered in `PafDbContext` with EF Core 10 `HasQueryFilter(name, expression)` directly: the kit's `AppendGlobalQueryFilter` (`src/BuildingBlocks/Persistence/ModelBuilderExtensions.cs`) is `internal` and not reachable from this module. It composes by AND with the Finbuckle tenant filter (also named) and the soft-delete filter. See ADR 0003.
- **Never call bare `IgnoreQueryFilters()`** in this module, and never set `IgnoreQueryFilters` on a specification (the kit's evaluator translates it to the bare form). Cross-unit aggregation disables only the unit filter by name: `IgnoreQueryFilters([PafQueryFilters.Unidade])`.
- **Current unit**: scoped `IUnidadeCorrente` (`Escopo/`), filled by whoever resolves the credential via `Definir`. The filter applies to every entity implementing `IEscopoUnidade` (marker-driven, not a list). Empty current unit = the filter returns NO rows (fail-closed). `Parametro` has its own filter: empresa rows (`UnidadeId` NULL) always visible. No unit filter on `Unidade`, `UsuarioUnidade`, `SessaoEstacao`, `AtividadeSessao` (tenant only).
- **No soft delete** on PAF entities: a soft-deleted `Chamado` would still hold the partial unique index (arquitetura 4.1).
- **Instants come from PostgreSQL** (`now()` defaults); never assign them from C#. `DataOperacional` (Ficha, Atendimento) and `DataElegibilidade` are STORED generated columns in America/Sao_Paulo (`Data/PafSql.cs`), so rewriting `ElegivelDesde` rewrites `DataElegibilidade` in the same write. Every state change of `Atendimento` increments `Versao`.

## Unit scope in requests

- `IUnidadeCorrente` sources, in middleware order: `Conferencia/ConferenciaRequisicaoMiddleware` (station credential, claim `PafClaims.Unidade` = `paf_unidade`, checked against `VinculoEstacao`), `Sessao/SessionCheckMiddleware` (person with a PAF session), then `Escopo/UnidadeCorrenteMiddleware`: header `X-Paf-Unidade` only when neither set the unit (root tenant, root operator in a client tenant), 403 outside the person's effective scope; a station (recognised by `PafClaims.Papel`, like the other middlewares) sending another unit in the header gets 403. Ponytail: the header goes away when the session covers root.
- Unit-scoped writes take the unidade from `IUnidadeCorrente.Exigir()`, never from the body.
- Explicit cross-unit paths (only `IgnoreQueryFilters([PafQueryFilters.Unidade])`): `ListFilasConsolidadas` (caller's scope) and `UpdateContratoUnidade` (Codefi operator). `Architecture.Tests/PafQueryFilterTests` scans the PAF IL and fails on the bare form or on a specification overriding `IgnoreQueryFilters`.
- Statistics (RF07, E0): `GET api/v1/paf/estatistica` (`Estatisticas.View`; type 4 also `Estatisticas.ViewPorAtendente`, else 403) reads the caller's effective scope, never the current unit. Every `unidades`, `filas` or `prioridades` id outside the scope is 403, unknown is 400, and a fila/prioridade outside the asked `unidades` is 400: a filter is never narrowed silently. Each type is an `IConsultaEstatistica` registered in `PafModule` (E1 types 1-6, E2 7-8, E3 9-10); an unregistered type answers an empty table.
- Statistics types 1-6 (E1, `Features/v1/Estatistica/Atendimentos/`): realizados = `Encerrado` with the atendimento's own `DataOperacional` in the inclusive period (filas and prioridades restrict the population); one grouped query returns sums and counts per (unidade, fila, estação, usuário) and every row, per-unidade subtotal (`Totais` with `UnidadeId`) and scope total (`UnidadeId` null) divides from those sums, so totals are weighted, never a mean of means. Wait = `ChamadoEm - ElegivelDesde` (a recall never moves it), service = `EncerradoEm - IniciadoEm`. Types 1/2 (D08) are the same per-fila table ranked by wait / by service; type 3 lists every guichê station, deactivated included, zeros dropped only by `somenteEstacoesComAtendimento`; type 4 names come from `IUserProfileService.GetListAsync` (never a JOIN into identity); type 5 groups started, non-cancelled atendimentos by the hour of `IniciadoEm AT TIME ZONE 'America/Sao_Paulo'` in raw SQL (explicit `TenantId` and unidades: neither `EF.Functions.AtTimeZone` nor `TimeZoneInfo.ConvertTimeBySystemTimeZoneId` over `DateTimeOffset` translates in this Npgsql); type 6 counts não efetuados (not started, not cancelled) and cancelados (started or not) per fila. Command timeout 15 s (`EstatisticaAtendimentos.PrazoConsulta`). Tests: `Integration.Tests/Tests/PAF/PafEstatisticaAtendimentosTests`.
- Statistics types 7 and 8 (E2, `ConsultasDeFichas.cs`): every ficha whose own `DataOperacional` is in the period, no exclusion; fila/prioridade filters are those of the emission, so a forwarded ficha counts once under its original fila. Type 7 groups by the hour of `CriadoEm` in America/Sao_Paulo (only hours with fichas); type 8 by emitting station and channel (`Guichê`/`Totem`), deactivated stations included. Every row leads with the unidade name and carries its `UnidadeId`; `Totais` = one `Subtotal` per unidade, then the scope `Total` (`UnidadeId` null) last. The hour uses `TimeZoneInfo.ConvertTimeBySystemTimeZoneId(...UtcDateTime, ...)`, which Npgsql translates to `AT TIME ZONE`; `EF.Functions.AtTimeZone` is SQL Server only and throws. 15 s command timeout.
- Statistics types 9 and 10 (E3, `ConsultasDeTotais.cs`): one query JOINs `Filas` (unit filter lifted by name on both sides) and counts per (unidade, fila, the fila's CURRENT `SetorId`, prioridade, estado); `agrupamento` regroups by fila or by (unidade, setor), so moving a fila to another setor regroups the past and "Sem setor" (`TotaisAgrupados.RotuloSemSetor`, last within its unidade) is one group per unidade. Type 9 (D07) = realizados with one count + % column pair per prioridade NAME of the consulted unidades (active ones from the cadastro, zeros included, ordered by highest `Valor`), % over the row total, then Total + % over the scope total. Type 10 = every atendimento of the period split into atendidos (Encerrado), em atendimento, não efetuados (Aguardando/Chamado) and cancelados, then the row total; every % over the scope total. Percentages come from integer sums in every row, subtotal and total (null when the divisor is 0), never averaged. Tests: `Integration.Tests/Tests/PAF/PafEstatisticaTotaisTests`.
- Demo data: `Data/PafDemoSeeder`, called by the DbMigrator `seed-demo` verb only, never by tenant provisioning.

## Station credential (`Estacoes/`, `Conferencia/`, `Autorizacao/`)

- Claims in `Contracts/Authorization/PafClaims` (`paf_papel`, `paf_estacao`, `paf_unidade`, `paf_vinculo`, plus the kit's `tenant`, `sub`, `jti`); role values in `PafPapeisEstacao` (`Emissao`, `Painel`). Single definition: never redeclare claim names elsewhere.
- `ConferenciaRequisicaoMiddleware` runs for every authenticated request of the host: 403 when the `tenant` header or `?tenant=` differs from the token's tenant claim (root operators exempt, stations never); for a station token it checks the live `VinculoEstacao` and the active `Estacao`, sets the unit, and marks `HttpContext.Items["paf:estacao-conferida"]`, which `EstacaoAuthorizationHandler` reads for policies `PafEstacaoEmissao` / `PafEstacaoPainel`.

## Realtime (`TempoReal/`)

- `PafHub` at `/api/v1/paf/hub` (`PafHubRota.Caminho`), policy `PafHub`, groups `PafGrupos` (`paf:{tenant}:unidade:{guid}` and siblings). Writes go through `AvisosTempoReal.GravarAsync` inside the transaction and `EnviarAsync` after commit; the outbox stores the full type name of the `*Paf` events, so renaming one orphans stored rows.
- `PafHubFilter` revalidates on connect and on every client call (live `VinculoEstacao` through `Conferencia/CredencialEstacao`, active kit session through `ISessionService`), aborts on refusal, and installs the token's tenant in the hub scope. Registered with `AddSignalR().AddHubOptions<PafHub>`: a bare `Configure<HubOptions<PafHub>>` is silently ignored (SignalR uses per-hub options only when `HubOptionsSetup<PafHub>` marked them set). Test clients make one `EntrarNoGuiche` round trip after `StartAsync` (`PafOperacao.ProntaAsync`), because the handshake returns before the groups are joined: resolve `PafDbContext` lazily inside the hub, never by constructor.
- `PafHubFilter` also judges an impersonation connection, on connect and on every call, by `act_tenant` = root and `IImpersonationGrantService.IsRevokedOrEndedAsync(jti)` (5 s limit): a revoked or ended grant aborts the connection on its next call, which over WebSockets is the only check after the upgrade.
- `ConexoesPaf` is the connection registry (local list for `Abort` plus `RegistroConexoes` in Valkey, see below). A person connection joins the guichê group of its session's active `SessaoEstacao` on connect; the guichê screen invokes `EntrarNoGuiche` (`PafHubChamadas`) after selecting and after every reconnect. Hooks, called after the write is committed: `EncerrarSessaoAsync` from `RevogacaoSessao`, `EndSessao` (logout), the login's single session (previous sessions) and the refresh refused for licence; `EncerrarEstacaoAsync` from `RevogarVinculo`, `GerarVinculo` (device replaced) and `DisableEstacao`. `MoverSessaoParaGuicheAsync` from `SetGuiche` (the new guichê, and null for a dead occupant it released).
- `RegistroConexoes` (Valkey, keys `paf:{t}:conexoes:{sessao|concessao|estacao}:…` as ZSETs scored by expiry, `paf:{t}:conexao:{id}:grupos|guiche`, global `paf:sessoes-caidas`) reaches the connections of every instance: hooks and `RemoverDeTodosOsGruposAsync` (by session, by grant `jti`) leave groups through `IHubContext.Groups` (crosses the backplane); only the holding instance aborts. Every group join goes through `ConexoesPaf.EntrarNoGrupoAsync`, so the groups are recorded. Valkey down or absent (the test host): local list only, 500 ms ceiling per call. Person and impersonation join `paf:{t}:unidade:{u}` (person: `EstadoSessao`, else the licence unit; impersonation: the grant's own unit from `UnidadeDaConcessao`, never the user group).
- `RenovacaoPelaConexao` (hosted, per instance, step = min(interval, grace)/2): renews the registry entries it holds (validity 2 × interval), renews the live `AtividadeSessao` mark of each session with a connection here (PostgreSQL, also without Valkey; only a live mark, spaced by the interval) and, on each renewed mark, its `ConjuntoLicencas` member in the unit of the row and on each write checks `UserSession` and user active; releases licence and guichê (`Licencas.LiberarAsync`) of a session whose last connection dropped longer than the grace ago, on any instance, only with Valkey. Options `PAF:Sessao` (`CarenciaReconexao` 2 min, `PrazoMarca` 10 min, `IntervaloRenovacao` 1 min) validated on start.
- Renewal hardening (review of wave 0): `RenovacaoPelaConexao` isolates each tenant and each drop (a tenant whose database fails is logged and skipped, the others and the grace release go on); `Licencas.RestaurarMembroAsync` (used by both renewals) rereads the `AtividadeSessao` row after restoring the member and releases it if the row is gone, so a logout or release racing the renewal leaves no ghost member. Tests: `PafRegistroConexoesTests.TenantComBancoFora_*`, `PafConjuntoLicencasTests.RestauracaoQueChegaDepoisDoLogout_*`.
- `SessaoInvalidada { SessaoId, Motivo }` (S04, contract `Contracts/v1/TempoReal/SessaoInvalidada.cs`): `ConexoesPaf.EncerrarSessaoAsync(tenant, sessao, motivo, ct)` sends it to the session's connection ids (local list + registry), one `Clients.Client(id)` at a time so a local one is flushed before the abort (the list overload goes through the Redis backplane even for local ids), never to the user group; a failed or stalled send (5 s ceiling) is logged and the close goes on; then removes them from every group and aborts the ones held here; another instance's connection is aborted by the filter on its next call or by its holder's renewal cycle. `Motivo` is the sentence the screen shows (`GenerateTokenLicenseBehavior.MensagemSessaoUnica`, `EndSessaoCommandHandler.MensagemTela`, `RevogacaoSessao` maps its audit reason to `MensagemUnidadeRetirada`/`MensagemUsuarioInativo`, else the generic one), never the kit's audit reason. Repeat dropped by the session id: Valkey key `paf:{t}:sessao:{s}:invalidada` (SET NX, 1 h); without Valkey it counts as first (the local connections are aborted anyway). `Sessao/SessaoRevogadaPafHandler` consumes `SessionRevokedIntegrationEvent` (S01): releases licence and guichê, drops the Valkey state, closes with `MensagemSessaoEncerrada` (root tenant: connections only, no licence); a lost event is caught by `RenovacaoPelaConexao`. Front: the provider's handler (`tempo-real/sessao-invalidada.ts`, `node --test`) ignores another `sid`, toasts the reason and calls the kit `logout`. Tests: `PafSessaoInvalidadaTests`, `PafRegistroConexoesTests.DuasInstancias_SessaoInvalidada*` and `AvisoQueFalhaNoBackplane_*`.
- Every front client connects WebSockets-only with `skipNegotiation: true` (seção 11, 17/10/2026) and invokes nothing while not Connected. The .NET test clients stay on long polling (TestServer closes a WebSocket before the handshake).
- Real WebSocket E2E (O16): `src/Tests/PAF.Kestrel.Tests`, its own process with the host on Kestrel (`WebApplicationFactory.UseKestrel`, one host per process) and the front's client setup (WebSockets only, `SkipNegotiation`, `?tenant=` and `?access_token=`, upgrade status recorded): painel gets `SenhaChamada`, another client's `?tenant` gets 403 at the upgrade, the one-minute token (`JwtOptions:AccessTokenMinutes` = 1 there) is closed at `exp` and the reconnect renews through the secret, a revoked session survives until its next call and is then aborted for good (no automatic reconnect; the new upgrade gets 401). Not in the `Integration.Tests` filter: run the project itself.
- RNF18 measurement (O17): `src/Tests/PAF.Latencia.Tests`, its own process (two hosts, ModuleLoader reset), D20 volume (20 unidades × 3 totens, 2 painéis, 8 guichês, all on WebSockets, totens emitting during the run) on Kestrel with a real Valkey (backplane on) behind `RetransmissorComAtraso` (delays every chunk from Valkey). Samples = (call, painel) on one process clock, from the request leaving and from its 200 (the direct send often beats the 200, and the 200 waits up to 100 ms for it, so the from-200 number alone misses a slow delivery: a 1.1 s mutation in `EntregarAsync` gave from-200 p95 ~900 ms). Calls 100 ms apart across the tenant, the guichês of one unidade together. Gated, on both clocks: p95 < 1 s over 200 calls, the same with +50 ms on Valkey, two guichês of a unidade in the same second; the two-instance hop is printed as reference only. Run with `--logger "console;verbosity=detailed"` to read the percentiles.

## Session and licence (`Sessao/`)

- The access token carries the kit session id in claim `sid` (edit in the Identity token handlers, ADR 0008). The JwtBearer inbound map keeps it as `sid`.
- `GenerateTokenLicenseBehavior` / `RefreshTokenLicenseBehavior` are closed Mediator behaviors (confirmed applied by `PafSessaoLicencaTests`). Root tenant and users with no `UsuarioUnidade` pass straight through: no licence, no single session.
- First slice: no cascade, the principal unit (lowest `Ordem`) pays; the licence does not migrate on unit switch. The seat count is always `AtividadeSessao` rows fresher than 10 min, under `pg_advisory_xact_lock` of the unit.
- Licence set (S09, supersedes the count rule above outside the degraded mode): `ConjuntoLicencas` keeps one Valkey ZSET per tenant and unit (`paf:{t}:licencas:{u}`, score = expiry in the Valkey clock, `TIME` inside the script) plus the index `paf:{t}:sessao:{s}:licenca`. One Lua script releases the given members, returns the unit the session already holds (idempotent per session) or occupies the first candidate with balance, the caller's other sessions counting as free. `Licencas.ReservarAsync` takes a per-user advisory lock (login and refresh of the same user serialize, sessão única), reserves a provisional `reserva:{guid}` member (`PrazoReserva` 1 min), and `ReservaLicenca.ConfirmarAsync` swaps it for the session and the user's earlier sessions in one script, then writes `AtividadeSessao` (still the source of truth; the seat goes back if the commit fails).
- Degraded mode: Valkey not registered, disconnected, past the 500 ms deadline (connection and timeout errors only; a server error propagates), or the rebuild mark `paf:licencas:reconstruido` missing → the unit advisory lock and the `AtividadeSessao` count decide, as in the first slice. `RenovarMarcaAsync` also puts the member back in the unit of the PostgreSQL row (no cascade); `LiberarAsync` removes it. `ReconstrucaoLicencas` (hosted, every instance) rebuilds from fresh rows with an active kit `UserSession` on start, on `ConnectionRestored` and when the mark disappears; members untouched since the snapshot and not in PostgreSQL leave, newer ones and reservations stay; a tenant whose database fails is logged and skipped (its members return on renewal), never holding the global mark. Tests: `PAF.Tests/ConjuntoLicencasTests` (fixture `ValkeyPaf`, pausable and flushable), `Integration.Tests/Tests/PAF/PafConjuntoLicencasTests`.
- Licence cascade (S05, supersedes "no cascade, the principal pays" above): `Licencas.ReservarAsync` takes the candidates from `EscopoUsuario.EscopoEfetivoAsync` in scope order, keeps the ACTIVE ones with a valid `ContratoUnidade` and hands the ordered list to the set script (the first with balance, or the first `UltrapassarComAviso` one, wins); the degraded mode locks every candidate (`paf-licenca:{t}:{u}`) in id order before counting. Refusal messages by cause: no active unit, no active unit with contract, every candidate full. Login and refresh share it. Tests: `PafCascataLicencaTests` (every case with Valkey and degraded), `PafCascataRenovacaoTests` (host).
- Refresh (S05, L28 fixed): `RefreshTokenLicenseBehavior` validates the refresh token (`IIdentityService.ValidateRefreshTokenAsync`), finds the session by the kit digest of the refresh token (first 8 bytes of SHA-256, hex, as `RefreshTokenCommandHandler`) and, only for a session without a live mark, reserves BEFORE the kit handler rotates. A refusal is a 403 with no rotation and no revocation: the old refresh token revives the session once a seat frees. Revived in another unit than the one the screen had (`EstadoSessao`, else the expired row): the Valkey unit state is dropped and `UnidadeCorrenteAlteradaPaf` (method `UnidadeCorrenteAlterada.Metodo`, user group, outbox + direct) tells every window, which re-reads its context (`clients/dashboard/src/features/paf/unidade-corrente.ts`, wired in `guiche/hub-guiche.ts`; every reconnection re-reads too, because the window's own connection dies with the expired mark and the notice usually lands by the outbox copy after it reconnects). Open connections stay in the old unit group until S07 moves them.
- Re-occupation on request and hub (S06, ARQ seção 9 "sessão revivida"): a person token of a client tenant whose session has no live mark (grace release, expired mark) re-occupies through `ReocupacaoSessao.GarantirAsync` (same `Licencas.ReservarAsync` cascade, no new token), from `SessionCheckMiddleware` and from `PafHubFilter` on connect and on every call (root tenant skipped). Under the reservation's per-user lock it re-reads the mark (a REST request and a reconnection together occupy once) and the kit session (a login elsewhere wins); revived in another unit it drops the Valkey unit state and sends `UnidadeCorrenteAlteradaPaf`, like the refresh. Refusal: REST and the hub negotiate/upgrade get 401 with the cause (`Licencas.Mensagem*`); the filter throws `PafHubFilter.LicencaRecusadaException` (a `HubException` with the cause), aborting on a call; on connect it does not abort, so SignalR can send it as the close reason (expected, not exercised: in one instance the middleware refuses the upgrade first). Tests: `PafReocupacaoLicencaTests` (filter called directly, degraded mode).
- Licence history (S08, RF22, ARQ seção 9): `ConsumoLicenca` (`paf.ConsumosLicenca`, unit-filtered, written only by raw SQL) holds `Amostra` and `Excedente` rows (`Ocupadas`, `Limite`, `SessaoId` for the excess). `Licencas.ConfirmarAsync` writes one `Excedente` inside the occupation's transaction whenever the occupied seats exceed the contract (`UltrapassarComAviso`; `Recusar` never gets there), in both modes: a failed confirmation leaves neither the row nor the seat. `GET api/v1/paf/sessao/aviso-licenca` (no permission, own session only; 204 without excess or without a PAF session) returns the session's latest excess, read across units (`IgnoreQueryFilters([PafQueryFilters.Unidade])`, the licence unit may not be the current one); the dashboard shows it above the PAF screens (`features/paf/sessao/aviso-licenca*`, D03), closable per record. Tests: `PafConsumoLicencaTests`.
- Licence migration on manual unit switch (S07, supersedes "the licence does not migrate" above, L30): `SetUnidadeCorrente` checks scope and active, then in ONE transaction `Licencas.MigrarAsync` takes the per-user lock, then the session's guichê link (`VinculosGuiche.TravarAtivoDaSessaoAsync`), then the `AtividadeSessao` row (user, link, row: the order of `ConfirmarAsync` and `LiberarAsync`, so a login elsewhere or a logout alongside waits instead of deadlocking); the row lock is `FOR UPDATE`, so the renewal cannot restore the member in the origin. It then requires a valid `ContratoUnidade` in the destination (409 `MensagemDestinoSemContrato`) and moves the member with `ConjuntoLicencas.MoverAsync` (one script: balance of the destination checked before the origin loses anything, the session itself counting as free; 409 `MensagemDestinoLimite` touches nothing; `UltrapassarComAviso` accepts and writes the `Excedente`). Valkey not rebuilt or out: the count of fresh rows of the destination without the session, under the `paf-licenca:{t}:{u}` locks of origin and destination in id order; with the Valkey up but not rebuilt the member goes to the destination after the commit (`ConcluirMigracaoAsync`); with the Valkey out the state write fails anyway (503). Then the row moves (`UnidadeId`, `UltimaAtividadeEm = now()`), the guichê is released only now (`SoltarSemAtendimentoEmCursoAsync`, 409 with an atendimento in progress), `UnidadeCorrenteAlteradaPaf` is written to the outbox and the Valkey unit state is set (fails = 503, so without Valkey nothing changes). Any failure before the commit puts the member back in the origin (`DesfazerMigracaoAsync`, own 2 s deadline). After the commit: `ConexoesPaf.MoverSessaoParaUnidadeAsync` (own file `ConexoesPaf.Unidade.cs`) moves every connection of the session from the old unit group to the new one, the guichê group is left when this transaction released the link, and the notice goes to the user group. The dashboard still tells the other tabs by `BroadcastChannel` (single session = one browser); `hub-guiche.ts` re-reads on the notice. Tests: `PafMigracaoLicencaTests` (set and degraded, crossed switches 50 rounds, last seat, hub groups).
- Licence maintenance job (S08, ARQ seções 5 e 9): `ManutencaoLicencas`, Hangfire recurring `paf-manutencao-licencas` registered in `MapEndpoints` (cron `*/5 * * * *`, ponytail), iterates every client tenant in its own scope (`ProvisionamentoTenantPaf.AbrirEscopo`, 30 s per tenant, a failing tenant is logged and skipped): samples each unidade with a valid contract into the 5-min window start (`date_bin`, `ON CONFLICT DO NOTHING` on `UX_ConsumosLicenca_Amostra`; count = live non-reservation members of the Valkey set, or the live marks when the set is down or not rebuilt), deletes `AtividadeSessao` rows past `PrazoMarcaMinutos`, releases `SessaoEstacao` links of sessions without a live mark and of grants expired (`ConcessaoExpiraEm`) or ended/revoked/unknown (`IImpersonationGrantService.IsRevokedOrEndedAsync`, 2 s). Only the link is released; an atendimento in progress on the guichê stays. No connection is notified. Runs in the integration host too (in-memory Hangfire). Tests: `PafManutencaoLicencasTests`.
- `SessionCheckMiddleware` (module middleware) checks `sid` → active `UserSession` → fresh `AtividadeSessao`, fills `SessaoCorrente` and `IUnidadeCorrente` (Valkey state via `EstadoSessao`, else the licence unit), and renews the mark at most once a minute. The current unit must be in the user's effective scope (`EscopoUsuario`), else the session is revoked (RF08); a disabled unit is NOT checked (open sessions run until they end). Each renewal also checks the user is active (`IUserProfileService`), revoking otherwise. Root tokens get the `UserSession` check too (read in a root-tenant scope when the request targets a client tenant), never the licence. Tokens with `act_sub` or `paf_papel` (`PafClaims.Papel`, same test as `ConferenciaRequisicaoMiddleware`) are not handled here, except for the impersonation barrier below.
- Impersonation barrier (`Sessao/ImpersonacaoPaf`, RF22/RNF15): only the Codefi's impersonation (`act_tenant` = root tenant) operates the PAF. `SessionCheckMiddleware` answers 403 to any other `act_sub` token (missing `act_tenant` included) on every path under `/api/v{n}/paf` (path test, case-insensitive, hub included), before authorization; kit routes keep accepting the client admin's impersonation. Beyond the barrier, an `act_sub` token on a PAF route gets the grant's own branch (S10B): `ConcessaoCorrente` (grant id = token `jti`), no `SessaoCorrente`, no licence, no `AtividadeSessao` row, and the single-session rule never reaches it. `UnidadeDaConcessao` sets `IUnidadeCorrente` from Valkey key `paf:{t}:concessao:{jti:N}:unidade` (TTL = token `exp`); missing or out of the impersonated user's scope, it recreates it by the station of the grant's active `SessaoEstacao`, else the current unit of the user's freshest live session, else the principal (same order from PostgreSQL without Valkey). `X-Paf-Unidade` is ignored for `act_sub`. `SetUnidadeCorrente` under a grant switches only that key (scope and active checks as the session, releases the grant's guichê link, 503 without Valkey) and never touches the user's session or tabs.
- `AtoImpersonacao` (S11A, D28): every PAF write under the Codefi's impersonation records one row (operator `act_sub`, grant `jti`, current unit, atendimento when any) in the write's own transaction; no `act_sub`, no row. Cadastro commands carry the marker `Contracts/v1/IEscritaDeCadastro`, and `Sessao/AtoImpersonacaoBehavior` (constrained open generic) notes the act before the handler, so the handler's `SaveChanges` writes it; a marked handler that writes around the context (`ExecuteUpdate`, raw SQL) calls `AtosImpersonacao.GravarAsync` inside its transaction (as `RevogarVinculo`), and a tracker clear re-notes with `Anotar` (as `GerarVinculo`), else the behavior throws. `Architecture.Tests/PafAtoImpersonacaoMatrizTests` fails any write command (`IBaseCommand` in the PAF assemblies) neither marked nor in its exclusion list with a reason; only S11 empties the guichê exclusions. Unit-scoped: an impersonated write with no current unit gets 403.
- Guichê under impersonation (S11, RF22, ARQ seção 9): the post's owner per request is `Sessao/DonoPosto` (`ConcessaoCorrente` when set, else `SessaoCorrente`; `UsuarioId` = `sub`, so atendimentos and the F17 owner check are the impersonated user's). `SetGuiche` under a grant writes `SessaoEstacao.CriarParaConcessao` (`ConcessaoId` = `jti`, `ConcessaoExpiraEm` = token `exp`), only on a free guichê: a live session's guichê is 409 and its link stays; a real user's selection releases a grant link expired (`ConcessaoExpiraEm`) or ended/revoked/unknown in the kit (`IsRevokedOrEndedAsync`, 2 s) and moves the grant's connections out, a live grant's is 409 `MensagemEmUsoPeloSuporte`; the race ends on `UX_SessoesEstacao_EstacaoAtiva` (409); the impersonated user's own pendência is resumed. Guichê reads (`posto`, `guiches`, VIP filas, destinos, fichas em espera), `VinculosGuiche.AtivoDoDonoAsync`/`TravarAtivoDoDonoAsync` and `PafHub` (`EntrarNoGuiche`, connect; `ConexoesPaf.MoverConcessaoParaGuicheAsync`) follow the grant's link. Every guichê command and `SetUnidadeCorrente` carry `IEscritaDeCadastro` and write the act in their transaction: `OperacaoGuiche.TravarAsync` (rechamar, iniciar, encerrar, cancelar, encaminhar), `ChamadaDeFicha.ConfirmarAsync` (the three calls; chamar-próximo drops the act of a rolled-back attempt with `Descartar`), `SetGuiche` (names a cancelled pendência), `SetUnidadeCorrente` grant branch; an idempotent return calls `Descartar`. `Anotar` names the atendimento on an act the behavior noted without one, while unsaved. Screen: badge `guiche/selo-impersonacao.ts`. Tests: `Integration.Tests/Tests/PAF/PafImpersonacaoGuicheTests`.
- PAF-born revocation goes through `RevogacaoSessao` (release licence and guichê, drop the Valkey state, revoke the `UserSession`). `SetUsuarioUnidades` uses it for every live session whose current unit was taken out. `CreateUnidade` does NOT add the creator to the new unit's scope.
- Effective scope (RF08, ADR 0006, C01): `EscopoUsuario.EscopoEfetivoAsync(usuarioId)` is the single definition, read by both middlewares, `SetUnidadeCorrente`, `ListUnidades` (and `guiche/unidades`, which drops inactive ones), `ListFilasConsolidadas`, `Get/SetUsuarioUnidades` and `ExigirAsync`; never query `UsuariosUnidade` for a scope decision. List scope = the `UsuarioUnidade` rows by `Ordem`. Escopo empresa (`paf.PerfisUsuario.EscopoEmpresa`; no row = list scope) = its single principal row, then every unidade of the tenant by `CriadoEm`, created-later and inactive ones included (the licence cascade skips inactive ones). No principal row = empty scope (fail-closed). `PerfisUsuario` (PK `UsuarioId`, tenant only) also holds `Funcao` (free-text job title, D15) and `Ramal`, edited by C12.
- Scope grants (`UsuariosUnidade` GET/PUT, body `EscopoEmpresa`): the tenant admin (`EscopoUsuario.AdministraTenantAsync` = escopo empresa profile OR holder of `Unidades.Create`, the latter kept by the decision of 17/10/2026 until RF23 seeds the first escopo empresa) reads and edits any user, grants any ACTIVE unidade of the tenant (else 400) and grants escopo empresa; anyone else gets 403 for escopo empresa and keeps the RF08 subset rule on the effective scope (grant only inside his scope, touch only users whose scope fits in it, never an escopo empresa user). Escopo empresa carries exactly one unidade, the principal (400). `SetUsuarioUnidades` serializes per user with `pg_advisory_xact_lock(hashtextextended('paf-escopo:{tenant}:{usuario}'))` and revokes on the effective-scope delta after commit.
- Unidades cadastro (RF23, C02): create, disable and enable need `EscopoUsuario.AdministraUnidadesAsync` (escopo empresa profile AND a principal row; holding `Unidades.Create` is not enough, unlike `AdministraTenantAsync`), 403 `MensagemSoAdministradorDaEmpresa`; update needs the unidade in the effective scope. `GET unidades/administracao` returns that same rule for the screen buttons. `ListUnidades` carries the contract in force (`ContratoVigenteResumoDto`, same validity as the licence, latest start wins), a third explicit cross-unit path (`IgnoreQueryFilters([PafQueryFilters.Unidade])` on `ContratosUnidade`). - Codefi operator side (RF23, C08): `GET api/v1/paf/operador/unidades` (`Unidades.Operar`, root only) lists every unidade of the tenant in the `tenant` header (initial first, no scope join) with all its contracts, newest start first, read with `IgnoreQueryFilters([PafQueryFilters.Unidade])` (fourth explicit cross-unit path). `Create/UpdateContratoUnidade` refuse a validity overlapping another contract of the same unidade (inclusive days, null end = open) with 409 `VigenciaContrato.MensagemSobreposta`, under `pg_advisory_xact_lock(hashtextextended('paf-contrato:{tenant}:{unidade}', 0))` taken before the overlap read (ponytail: EXCLUDE over a daterange needs `btree_gist`). A contract of another tenant's unidade is 404 by the tenant filter. Screen: `clients/admin` `/paf/unidades?tenant=<id>` (every call sends that tenant explicitly), menu section from `features/paf/operador/menu-operador-paf.ts` by one line in the kit `nav-items.ts`. Tests: `PafOperadorUnidadesTests`, `clients/admin/src/features/paf/operador/vigencia.test.ts` (`node --test`); walk `clients/admin/tests/e2e/paf-operador-contratos.walk.mjs` (real API with outbox and Hangfire, admin under `vite preview`).
- `UX_UsuariosUnidade_Ordem` (UsuarioId, Ordem, TenantId) is a `DEFERRABLE INITIALLY DEFERRED` unique constraint created by raw SQL in migration `EscopoEmpresaPerfisUsuario` and absent from the EF model (as a model index EF refuses a position swap): a duplicated principal fails at COMMIT, not at the INSERT.
- Routes under `api/v1/paf/sessao`: `unidade-corrente`, `guiche` (`Permissions.PAF.Guiches.Selecionar`), `logout`.
- User cadastro (RF08, RF22, C12, `Features/v1/Usuarios`, `Usuarios.View` / `Usuarios.Manage`): `GET usuarios` lists only the users `ExigirAlcanceSobreAsync` lets the caller reach (empty scope fits anyone); `POST usuarios` (login = e-mail, D14) checks grant (`UsuariosUnidade/ConcessaoDeEscopo`, shared with `SetUsuarioUnidades`), role and e-mail BEFORE `RegisterAsync`, then role, `PerfisUsuario` (`Funcao`, `Ramal`), scope (by sending `SetUsuarioUnidadesCommand`) and `AdminConfirmEmailAsync` LAST: a failure in between leaves an unconfirmed user the kit refuses at login, and the compensation deactivates him (`ToggleStatusAsync`, logged on failure). `PUT usuarios/{id}` edits name (kit), `Funcao`, `Ramal`; `POST usuarios/{id}/desativar` = reach check, kit `ToggleStatusAsync` (the kit accepts only a kit `Admin` actor and never a kit `Admin` target: a PAF Administrador without the kit role gets the kit's 403, pinned by `PafUsuariosTests.Desativar_PorAdminDaFilialSemPapelAdminDoKit_KitRecusaSemEfeito`), then `RevogacaoSessao` for every active kit session and licence row; `POST usuarios/{id}/copiar-perfil` copies the source's PAF product roles and stored scope (both users in reach). Roles: only `PapeisPadrao`'s three (`PapeisDoUsuarioPaf`), granted only by a caller holding every permission the tenant's role carries today; kit roles are never touched.
- Releasing a user's atendimentos (RF08 scope edit with `SetUsuarioUnidadesCommand.CancelarAtendimentosEmCurso`, RF22 deactivation): `Features/v1/Usuarios/AtendimentosEmCursoDoUsuario` is a fourth explicit cross-unit path (`IgnoreQueryFilters([PafQueryFilters.Unidade])` on `Atendimentos` and `Fichas`, `Chamado`/`EmAtendimento` with the user's `UsuarioId`), listed by `GET usuarios/{id}/atendimentos-em-curso`. The cancel switches `IUnidadeCorrente` to each atendimento's unidade, goes through `OperacaoGuiche.TravarFichaAsync` + `CancelarTravadoAsync` (F04), re-checks user and state under the lock (skips, never cancels for someone else), writes the impersonation act, and restores the caller's unidade; notices go by `ConfirmarEAvisarTodosAsync` with the scope edit's own commit. Tests: `Integration.Tests/Tests/PAF/PafUsuariosTests`. Screen: `/paf/usuarios`.
- Per-user permissions (RF08, C15, `Features/v1/Usuarios/Permissoes`): `GET`/`PUT usuarios/{id}/permissoes` (`Usuarios.View` / `Usuarios.Manage`, reach by `ExigirAlcanceSobreAsync`). Each user's individual PAF permissions live in a personal kit role `PAF-usuario-{id:N}` (`PermissoesIndividuais`, created on the first non-empty save through `IRoleService`/`IUserRoleService`, no kit edit; ponytail: it shows in the kit roles screen). Roles add up: the product role and the kit `Basic` role (which carries the five PAF basics) stay, so the panel only ADDS on top of them; a role or basic permission cannot be removed per user. The four RF08 blocks are `GruposPermissoesPaf.Todos`, the single definition (every non-root `PafPermissions.All` entry once, pinned by `PAF.Tests/GruposPermissoesPafTests`; Painel Chamador is empty, the painel runs on the station credential); anything outside is 400. The caller may only add or remove permissions he holds (symmetric difference against his set, else 403 before any role exists). The kit writes share the scope's connection and cannot join a PAF transaction, so the per-user serialization is a SESSION advisory lock `paf-permissoes:{tenant}:{usuario}` on the opened connection (unlock under its own 5 s deadline), and the impersonation act goes in its own PAF transaction right after. `CopiarPerfil` copies the source's individual set under the same lock and check (pre-checked before the scope copy). Permissions take effect on the next request (kit permission cache invalidated by the role writes). Tests: `Integration.Tests/Tests/PAF/PafPermissoesUsuarioTests`; front `usuarios/permissoes-usuario.tsx`, rules `usuarios/permissoes-regras.ts` (`node --test`).

Tests: `PafSenhaUsuarioTests`, and `PafLogSemDadosPessoaisTests.SenhaDefinidaPeloAdministrador_*` for the log.

## Operational flow (`Features/v1/Fichas`, `Features/v1/Atendimentos`, `Features/v1/Painel`)

- Emission: `POST api/v1/paf/estacao/emissao/fichas` (policy `PafEstacaoEmissao`, header `Idempotency-Key` required, kit `WithIdempotency` in front). Number = day max + 1 (or `NumeroInicial`), day and window from the PostgreSQL clock; `UX_Fichas_Numeracao` retries in a new transaction (max 10, logged); `UX_Fichas_ChaveIdempotencia` returns the stored ficha.
- Guichê emission (RF11, F12; `Permissions.PAF.Fichas.Emitir`, basic): `POST api/v1/paf/guiche/fichas` (`Idempotency-Key` required, kit `WithIdempotency`) and `GET api/v1/paf/guiche/emissao`. Single core `Features/v1/Fichas/EmitirFicha/EmissaoDeFicha` (validation, window, coverage lock, numbering retry, key replay, notice) takes `PedidoEmissao` with `CanalEmissao` and the emitting station as data; the totem handler checks its emission role first, the guichê handler takes the station of the session's link (`OperacaoGuiche.ExigirAsync`, 409 without one), 409 on an inactive station, 404 for a fila outside the current unit, any fila of the unit otherwise. Same number sequence as the totem. `EmitirFichaNoGuicheCommand` is `IEscritaDeCadastro`: the core discards the act after each tracker clear (a collided attempt's act names a rolled-back atendimento) and re-notes it with this attempt's atendimento, and discards it on a key replay (exercised under impersonation only after S11). The GET lists every fila of the unit (`Ativa`, `ForaDoHorario`, `Emissivel`, `UltimaChamadaEm` in SP, active covered prioridades) in `ordenacaoFilas` order (`ordem` = this guichê's `Guiche`-role order, then the others by name) and `UltimaFicha` = the guichê's last `Canal = Guiche` ficha of today through `ImpressaoDaFicha.LerAsync`; the screen's "reimprimir a última" re-reads it (no `FichasDoDia.View` needed). Screen: `guiche/emissao-guiche.tsx` on the guichê page (pure rules `emissao-guiche-regras.ts`, `node --test`). Tests: `Integration.Tests/Tests/PAF/PafEmissaoGuicheTests`.
- Guichê (`Permissions.PAF.Atendimentos.Operar`, basic; guichê from the session's `SessaoEstacao`): `POST api/v1/paf/guiche/chamar-proximo`, `POST api/v1/paf/guiche/atendimentos/{id}/{rechamar|iniciar|encerrar|cancelar}`. Call = candidate `FOR UPDATE OF a SKIP LOCKED`, then all rows of the ficha `FOR UPDATE SKIP LOCKED` in id order (savepoint rollback on skip); other operations lock the ficha rows waiting, in id order, and re-validate. Every state UPDATE stamps `now()` and increments `Versao`. Option "respeitar ordem das filas" = key `respeitarOrdemFilas` in `Estacao.Configuracao` (ponytail).
- Guichê link lock: the call and every release of a session's guichê (switch, unit change) take `SELECT ... FOR UPDATE` on the session's `SessoesEstacao` row inside their transaction (`VinculosGuiche.TravarAtivoDaSessaoAsync`, `SoltarSemAtendimentoEmCursoAsync`), so no guichê is released with an atendimento `Chamado` on it. Both throw without an open transaction.
- Ficha lock (`OperacaoGuiche.TravarFichaAsync`, F01): every state change outside the chamar-próximo selection enters here, with or without a guichê. Unit-filtered read of the `FichaId` (other unit = 404), then all rows of the ficha `FOR UPDATE ORDER BY "Id"` (never the target row first: entering by different rows would deadlock), then the target re-read; throws `InvalidOperationException` without an open transaction. `TravarAsync` is the guichê wrapper (404 before locking when the atendimento is not on this guichê). `SoltarVinculoDeEstacaoInativaAsync` releases the link of a deactivated station in the caller's transaction; guichê encerrar and cancelar call it, and every later path that ends an atendimento on a station calls it too, never a copy.
- Owner of the atendimento (RF04, F17): `TravarAsync` refuses with 409 `MensagensGuiche.MensagemDeOutroUsuario`, before any write, an atendimento on this guichê whose `UsuarioId` (re-read under the ficha lock) is not `Guiche.UsuarioId` (the impersonated user under impersonation): rechamar, iniciar, encerrar, cancelar and encaminhar act only on the caller's own atendimento; chamar is already refused by the guichê's in-progress check. The pendência release of `SetGuiche` cancels another user's atendimento by design, so it enters by `TravarFichaAsync`. Tests: `Integration.Tests/Tests/PAF/PafDonoAtendimentoGuicheTests`.
- Guichê screen reads (`Permissions.PAF.Guiches.Selecionar`, basic, no cadastro permission): `GET api/v1/paf/guiche/unidades` (only `Id` and `Nome` of the ACTIVE unidades of the caller's scope), `guiches` (active guichês of the current unit, with the occupant's user name and the senha of another user's pendência), `posto` (current unit, selected guichê, the caller's own atendimento in progress, never another user's).
- Pendência on selection (seção 5, RF04): an atendimento `Chamado`/`EmAtendimento` left on the guichê by a released link. Its own user resumes it by selecting the guichê again; another user gets 409 unless `SetGuicheCommand.LiberarPendencia`, which cancels it (RF12, `Chamado` or `EmAtendimento`) in the selection's transaction, under the ficha lock, with `AtendimentoAtualizadoPaf` after commit.
- RF12 cancel outside the guichê (F04): `POST api/v1/paf/fichas/atendimentos/{id}/cancelar` (`FichasDoDia.Cancelar`, not basic; the guichê's own cancel stays under `Atendimentos.Operar`). Single service `OperacaoGuiche.CancelarAsync` (locks the ficha) / `CancelarTravadoAsync` (caller already holds the lock): Aguardando, Chamado or EmAtendimento → Cancelado with `Versao+1`, else 409 `MensagemNaoCancelavel`; only Chamado/EmAtendimento release the waiting siblings; a deactivated station's link is released in the same transaction. Returns `AtendimentoAtualizadoPaf` plus one `FilaAtualizadaPaf` per touched fila, written by `ConfirmarEAvisarTodosAsync` before the commit and sent after it. The pendência cancel of `SetGuiche` calls this service; F07, F14, C05 and C12 call it too, never a copy. Tests: `Integration.Tests/Tests/PAF/PafCancelamentoFichaTests`.
- Reabilitar (RF12, F05; `Permissions.PAF.FichasDoDia.Reabilitar`, no guichê): `POST api/v1/paf/fichas/atendimentos/{id}/reabilitar`. Under the ficha lock: only `Cancelado`; with `somenteFichasDaDataAtual` on, `DataElegibilidade` BEFORE the rewrite must be today (SP, database clock), else 409 "emita ficha nova"; 409 naming the guichê when a sibling is `Chamado`/`EmAtendimento`. One UPDATE ends the eligibility cycle: `Aguardando`, `ElegivelDesde = now()`, `ChamadoEm`/`UltimaRechamadaEm`/`IniciadoEm`/`CanceladoEm`/`EstacaoId`/`UsuarioId` NULL, `Versao + 1`; `CriadoEm`, `DataOperacional` and `Rechamada` rows untouched (place in the queue comes from creation). Notices: `AtendimentoAtualizadoPaf` (`Aguardando`) and `FilaAtualizadaPaf`; the painel reducer drops the entry on `Aguardando` with a higher `Versao`.
- Fichas do dia (RF12, F06; `Permissions.PAF.FichasDoDia.View`): `GET api/v1/paf/fichas/atendimentos?data=&filaId=&estado=` lists one line per atendimento of the CURRENT unit whose `DataOperacional` is `data` (default: today by the PostgreSQL clock in SP), so a forward made after midnight lists under the new day. Raw SQL with explicit `"TenantId"` and `"UnidadeId"`; `EsperaSegundos` is computed by PostgreSQL from `ElegivelDesde` to `ChamadoEm`, else `CanceladoEm`, else `now()`. `TotalAguardando` counts Aguardando of the same day and fila, ignoring the estado filter. Newest first, capped at `MaxAtendimentos` (1000) with `Truncada` (ponytail: no paging). A fila of another unit is 404; an estado that is not an exact `EstadoAtendimento` name is 400. `GET api/v1/paf/fichas/{fichaId}/impressao` (same permission) returns the stored `FichaEmitidaDto` (emission atendimento, same senha and `IdentificadorPublico`, never a new number) through `Features/v1/Fichas/ObterImpressaoFicha/ImpressaoDaFicha.LerAsync`, the single reprint reader (F12, F15 reuse it). Screen `/paf/fichas-do-dia`: cancel (F04) and reabilitar (F05) by row, reprint through the totem's `FichaImpressa`, refresh button (ponytail: no realtime). Tests: `Integration.Tests/Tests/PAF/PafFichasDoDiaTests`.
- Fichas em atendimento (RF13, F07; `Permissions.PAF.FichasEmAtendimento.View`): `GET api/v1/paf/fichas/em-atendimento?filaId=` lists `Chamado`/`EmAtendimento` of the current unit through the unit filter (LINQ, no raw SQL), NO date predicate (the abandoned atendimento crosses midnight), stay = `now() - ChamadoEm` computed in PostgreSQL (`ListFichasEmAtendimentoQueryHandler.Consulta`, pinned by a `ToQueryString` test), longest first, `Total`, plus the unit's filas for the filter (no `Filas.View` needed). A `filaId` outside the current unit is 404, never an empty list. The row's cancel is F04's route. Screen `/paf/fichas-em-atendimento` (ponytail: 30 s polling, no realtime). Tests: `PafFichasEmAtendimentoTests`.
- Consultar ficha (RF18, F14; `Permissions.PAF.FichasDoDia.View`): `GET api/v1/paf/fichas/consulta?senha=&data=` reads the current unit only (unit filter; other unit = 404). The senha is matched as the printed `Letra || Numero` (a letter may hold digits, so it is never split), trimmed and upper-cased like `LetraDaSenha.Normalizar`, on the ficha `DataOperacional`; none is 404, more than one (a letter that changed hands mid-day) returns them all. Each ficha lists every atendimento in creation order with `AtendimentoOrigemId` (forwarding chain), `FimEm` = encerrado or cancelado, and `TempoTotalSegundos` = end (or the database `now()`) minus `IniciadoEm`, null when never started; `ConsultarFichaQueryHandler.AtendimentosDasFichas` keeps it server-side (a test pins `now()` in its SQL). Cancel and reabilitar are the F04/F05 routes, never a copy. Screen `/paf/consultar-ficha`. Tests: `PafConsultaFichaTests`.
- Ficha de espera (RF20, F15; `Permissions.PAF.FichasDoDia.View`): `GET api/v1/paf/fichas/reimpressao?senha=&data=&filaId=` returns a LIST of `FichaEmitidaDto` read by `ImpressaoDaFicha.LerAsync` (F06), never a new number. Same senha match as F14 (printed `Letra || Numero`, trimmed, upper-cased) on the ficha `DataOperacional`, narrowed to the ficha's own `FilaId` (the printed emission fila; a forward's destination fila is 404). Current unit only (other unit, other fila, unknown = 404 `MensagemNaoEncontrada`); all three parameters required, malformed = 400. More than one ficha (letter with digits printing the same text in the fila) returns all, in emission order (F11 VIP answers 404 there; owner has not decided which wins). Screen `/paf/ficha-de-espera` (fila options from the F06 list, ponytail), one Imprimir button per match through the totem's `FichaImpressa`. Tests: `PafReimpressaoFichaTests`, `ficha-de-espera/ficha-de-espera-regras.test.ts` (`node --test`).
- Station configuration (`GET api/v1/paf/estacao/{emissao|painel}/configuracao`) carries `Botoes`: filas of the emission role × prioridades, fila and prioridade active, covered and inside the time window (next line), ordered by station then fila order; empty for the painel.
- Guichê coverage (RF02, C07): `Features/v1/Filas/CoberturaGuiche` is the single definition: a (fila, prioridade) pair is covered while an ACTIVE station lists the fila in its `Guiche` role and enables the prioridade (emission and painel lists never count; who is logged in does not matter). ## Degraded mode without Valkey (S14, `Saude/`)

- `GET api/v1/paf/saude` (anonymous, no rate limit) runs only the checks tagged `paf`: `db:paf` (own `NpgsqlConnection`, no pool, `Timeout`/`Command Timeout` 1 s: a pooled connection returned at scope disposal held the probe until the server came back) and `valkey:paf` (`ConjuntoLicencas.ReconstruidoAsync`, 500 ms; Valkey down or set not rebuilt = `Degraded`, no Valkey configured = `Healthy`). 200 for `Healthy`/`Degraded`, 503 only for `Unhealthy` (PostgreSQL). The kit's `/health/ready` stays 503 without Valkey by design (its `redis` check); deploy and balancer probe `paf/saude`. Body: name, status and our fixed description, never the exception.
- Valkey connection string prazos the environments must use (O02): `connectTimeout=2000,syncTimeout=500,asyncTimeout=500,abortConnect=false` (`PafHostValkey.PrazosValkey`). With the Valkey stalled every kit call costs that plus up to the client's 1 s heartbeat; measured with it paused: guichê p95 ~2 s, emission ~5 s (kit idempotency filter, four calls), impersonation with a cold grant cache ~3.5 s.
- `CacheDeTenantSemValkey` wraps the kit's `OnTenantResolveCompleted` (PostConfigure, no kit file edited): the kit copies the tenant into the Finbuckle distributed cache store with no error handling, so without Valkey every request died in 500 before reaching the PAF. The copy waits 100 ms and goes on in the background; failures are logged. Ponytail: remove when the kit guards that write (upstream).
- `AvisosTempoReal.EnviarAsync` waits 100 ms for the fast path (the backplane publish ignores the token); past that the send goes on in the background, a late failure is logged, and the outbox delivers.
- `Licencas.ReservarAsync`, when the occupation does not answer, queues a fire-and-forget release of the provisional member (`ConjuntoLicencas.SoltarOcupacaoSemResposta`): a stalled Valkey runs the pending script when it returns and would hold a ghost reservation for `PrazoReserva`.
- Return of a stalled Valkey: the client drops the connection on the first timeouts, so `ConnectionRestored` triggers `ReconstrucaoLicencas`.
- Harness: `Integration.Tests/Tests/PAF/PafHostValkey` is a second API host with its own PostgreSQL and Valkey, both pausable, collection `PafHostValkey` with `DisableParallelization` (it sets `CachingOptions__Redis` as an env var during the host build, because the kit reads it eagerly, and resets the static `ModuleLoader`). ## Media cadastro (`Features/v1/Midias`, M03, RF03)

## Media read URL (`Midias/UrlLeituraMidia`, M04, ADR 0007)

- `UrlLeituraMidia.GerarAsync(midia, duracaoTotal, ct)` takes a mídia the caller already read through the unit filter (that read IS the unidade check) and the longest uninterrupted exhibition it will run with the URL (duration × repetitions; the preview passes one duration). Null when the mídia is inactive or its current envio (`EnvioId` + same `ChaveObjeto`) is not confirmed, refused or removed: such a mídia gets no URL. M06 drops those items.
- Validity = exhibition + `MargemLeitura` (10 min, now > 0), at least `PAF:Midia:PisoValidadeUrlLeitura` (1 h), at most `TetoValidade` = 7 days (R2) minus 15 min: the AWS SDK signs with its clock corrected to the store's, and a URL asked for exactly 7 days came out over 604800 s and silently fell back to SigV2 (`AWSAccessKeyId`/`Expires`/`Signature`), which R2 refuses. `ExpiraEm` is announced 2 s early (SigV4 floors the signing date and `X-Amz-Expires`). Same trap for any other presign near 7 days (`ValidadeUrlEnvio` accepts exactly 7 days).
- HybridCache key `paf:{t}:midia-url:{unidade}:{midia}:{envio}:{validitySeconds}` (a swap misses without removal), entry = validity − exhibition (a cached URL still covers the whole exhibition; the margin when the cap leaves no slack). The cache call has a 1 s deadline: past it the URL is signed without the cache with a warning (ids only, never the URL). A Valkey that answers within the deadline with an error is absorbed by HybridCache itself (logged at Error as "Cache backend read/write failure").
- The local store answers a server-relative path; it is resolved against `IRequestContext.Origin` (`OriginOptions:OriginUrl`, else the request host). No origin = exception, never a relative URL to a panel.
- Route: `GET midias/{id}/url` (`Midias.View`): 404 outside the unidade or tenant, 409 `MensagemSemUrl` for an inactive or unconfirmed mídia.
- Tests: `Integration.Tests/Tests/PAF/PafMidiaUrlTests` (RustFS: download, `X-Amz-Expires`, cache window, swap, 20 parallel, expiry, cap still SigV4, stalled cache; `PafMidiaUrlTenantTests`), `PafMidiaUrlValkeyTests` (local store + paused Valkey), `PAF.Tests/MidiaUrlLeituraTests`.

## Media schedules (`Features/v1/ProgramacoesMidia`, `Midias/AgendaMidia`, M05, RF10, D13)

- Routes under `api/v1/paf/programacoes-midia`: `POST` (`Programacoes.Create`), `GET` paged search (`Programacoes.View`), `PUT {id}` with the `Versao` read (409 when stale), `POST {id}/enable|disable` (`Programacoes.Update`, both raise `Versao`, no version asked), `DELETE {id}` (`Programacoes.Delete`, physical, 204). Every write locks the programação `FOR UPDATE` (`ProgramacaoTravada`); every command is `IEscritaDeCadastro` (delete is a tracked `Remove`, so the act rides on `SaveChanges`).
- Only an active mídia of the current unidade with a confirmed envio is programmable: create, edit and enable take it `FOR SHARE` (a concurrent disable or duration edit waits) and answer one 400 for inactive, unconfirmed, other unidade, other tenant or unknown. Disable never checks the mídia.
- Window = [HoraInicial, HoraInicial + duração da mídia × Repeticoes), São Paulo wall clock, computed on every read from the mídia's current duration (`HoraFinalSegundos` = seconds from midnight, 86400 = ends at midnight). D13: create, edit and enable refuse an end after midnight (400); overlap is accepted and resolved on air.
- `AgendaMidia` is the single "on air now" rule for M06/M08: `DeHojeAsync(db)` reads today and now from `PafRelogio` (never the C# clock) and today's programações (active, mídia active and confirmed, period and weekday mask); `NoAr` picks the window containing now, latest `HoraInicial` first, then newest `CriadoEm`, then `Id`. An end pushed past midnight by a later mídia edit plays until midnight and never spills into the next day.
- Search filters (AND, all optional): `nome` ILIKE contains with `%`/`_` escaped (explicit escape char: with the two-argument `ILike` a typed `%` still matched as a wildcard), `dias` any day of the mask, `hora` inside the computed window (end excluded, in SQL so paging counts right), `de`/`ate` overlapping the period, inclusive. Order: name, start, id; `sort` is not read.
- Tests: `Integration.Tests/Tests/PAF/PafProgramacoesMidiaTests` (also `PafProgramacoesMidiaTenantTests` for 403, other tenant and impersonation acts), `PAF.Tests/AgendaMidiaTests`.

## Media cleanup (`Midias/LimpezaMidia`, M09, RF03, ADR 0007)

- Hangfire recurring `paf-limpeza-midia` (cron `0 6 * * *` UTC = 03:00 BRT, ponytail), registered in `MapEndpoints` next to S08's; per client tenant in its own scope (`ProvisionamentoTenantPaf.AbrirEscopo`, 2 min per tenant, a failing tenant is logged and skipped). One batch of 200 per run, oldest first: envios with `RemovidoEm` NULL, `CriadoEm` older than 30 days (`lock-midia.json`) + `ValidadeUrlEnvio` (the lock counts from the PUT), no `Midias` row with that `EnvioId` (raw SQL, tenant in every table; the job has no current unit).
- A still-open envio is closed first (`RecusadoEm = now()`, conditional on still open): a confirmation racing the job then loses its own conditional UPDATE; if the confirmation won, the envio is left alone.
- Per envio: HEAD, `RemoveAsync`, HEAD; `RemovidoEm` only when the second HEAD is null (conditional, still unreferenced). The kit's S3 provider swallows every error in both calls (the cancellation too, answering null), so: each call has `PrazoArmazenamento` + `WaitAsync`, a null with the deadline fired is "no answer" and stops the tenant pass; and a null first HEAD only proves absence once the store answered with an object in the pass (probe = HEAD of the newest mídia's key), else the envio is `Indeterminados` and retried. Object still there after the remove = `Falhas` (bucket lock, permission), logged by envio id. Never the key in a log.
- Tests: `Integration.Tests/Tests/PAF/PafLimpezaMidiaTests` (RustFS; refused delete and erroring HEAD by a decorator of the kit storage; the real R2 lock is M11's proof).

## Station monitoring (O13, RNF20, ARQ seção 7)

- `TempoReal/MonitoramentoEstacoes` (singleton, called by `PafHub`): on a station connect, after the registry write, `UltimaConexao{Emissao|Painel}Em = now()`; on its disconnect, after the registry removal, `UltimaQueda{Emissao|Painel}Em = now()` unless another live connection of the same station and role exists (local list, then `RegistroConexoes.DaEstacaoAsync`), so a quick reconnection whose old connection drops later never shows as down. Raw SQL with `TenantId` and `UnidadeId`, column fixed by the claim's role (`PafPapeisEstacao`), own tenant scope (the hub filter installs no tenant on disconnect), 5 s ceiling; a failed write is logged (ids only) and never refuses nor breaks the connection. Guichê and administração have no row: they connect by the user's session.
- Columns are history; present state is the registry. `GET api/v1/paf/operador/estacoes` (`Unidades.Operar`, root only, tenant header; fifth explicit cross-unit path, `IgnoreQueryFilters([PafQueryFilters.Unidade])` on `Estacoes` and `Filas`) lists one row per (station, credential role), a combined station twice: `Conectada` = live registry entries (a dead instance stops renewing, so its role turns down within `ValidadeEntrada` = 2 × `IntervaloRenovacao`), or, when Valkey does not answer, the columns (`UltimaConexao` newer than `UltimaQueda`; `EstadoPeloRegistro` = false, a dead instance stays hidden). `Aviso` = station active AND role not connected AND `Estacoes/HorarioDeOperacao.EmOperacao` (D24: union of the windows of the unidade's ACTIVE filas, inclusive bounds, a fila without window = all day, no active fila = never) at the PostgreSQL clock in America/Sao_Paulo. The unidade's own `Ativa` is not checked.
- Screen: `clients/admin` `/paf/estacoes?tenant=<id>` (menu item in `menu-operador-paf.ts`, route in `routes.tsx`), polling 30 s; pure display rules in `features/paf/operador/monitoramento.ts` (`node --test`). Tests: `PAF.Tests/HorarioDeOperacaoTests`, `Integration.Tests/Tests/PAF/PafMonitoramentoEstacoesTests` (host without Valkey for the hub path; real Valkey with a simulated clock for another instance and a dead one); real-API walk `clients/admin/tests/e2e/paf-operador-estacoes.walk.mjs` (`seed-demo`, Valkey on, admin under `vite preview`, painel over a real WebSocket).
