# Module: PAF

PAF V2 queue management: the totem emits a ficha, the guiche calls it, the panel shows it. Module `Order = 900`, schema `paf`, `PafDbContext`.

## Rules

- **Domain language is Portuguese without accents** in identifiers (`Ficha`, `Fila`, `Guiche`, `Atendimento`, `Unidade`). Infrastructure (DbContext, initializer, module, endpoints plumbing) stays in English. See ADR 0004.
- **`Unidade` is a PAF entity**, not a kit concept. Every operational table carries `UnidadeId`. See ADR 0002.
- **Unit scope is a NAMED global query filter**, registered in `PafDbContext` with EF Core 10 `HasQueryFilter(name, expression)` directly: the kit's `AppendGlobalQueryFilter` (`src/BuildingBlocks/Persistence/ModelBuilderExtensions.cs`) is `internal` and not reachable from this module. It composes by AND with the Finbuckle tenant filter (also named) and the soft-delete filter. See ADR 0003.
- **Never call bare `IgnoreQueryFilters()`** in this module, and never set `IgnoreQueryFilters` on a specification (the kit's evaluator translates it to the bare form). Cross-unit aggregation disables only the unit filter by name: `IgnoreQueryFilters([PafQueryFilters.Unidade])`.
- **Current unit**: scoped `IUnidadeCorrente` (`Escopo/`), filled by whoever resolves the credential via `Definir`. The filter applies to every entity implementing `IEscopoUnidade` (marker-driven, not a list). Empty current unit = the filter returns NO rows (fail-closed). `Parametro` has its own filter: empresa rows (`UnidadeId` NULL) always visible. No unit filter on `Unidade`, `UsuarioUnidade`, `SessaoEstacao`, `AtividadeSessao` (tenant only).
- **No soft delete** on PAF entities: a soft-deleted `Chamado` would still hold the partial unique index (arquitetura 4.1).
- **Instants come from PostgreSQL** (`now()` defaults); never assign them from C#. `DataOperacional` (Ficha, Atendimento) and `DataElegibilidade` are STORED generated columns in America/Sao_Paulo (`Data/PafSql.cs`), so rewriting `ElegivelDesde` rewrites `DataElegibilidade` in the same write. Every state change of `Atendimento` increments `Versao`.

## Unit scope in requests

- `IUnidadeCorrente` sources, in middleware order: `Conferencia/ConferenciaRequisicaoMiddleware` (station credential, claim `PafClaims.Unidade` = `paf_unidade`, checked against `VinculoEstacao`), `Sessao/SessionCheckMiddleware` (person with a PAF session), then `Escopo/UnidadeCorrenteMiddleware`: header `X-Paf-Unidade` only when neither set the unit (root tenant, root operator in a client tenant), 403 outside the person's effective scope; a station (recognised by `PafClaims.Papel`, like the other middlewares) sending another unit in the header gets 403. Ponytail: the header goes away when the session covers root.
- Unit-scoped writes take the unidade from `IUnidadeCorrente.Exigir()`, never from the body.
- Explicit cross-unit paths (only `IgnoreQueryFilters([PafQueryFilters.Unidade])`): `ListFilasConsolidadas` (caller's scope) and `UpdateContratoUnidade` (Codefi operator). `Architecture.Tests/PafQueryFilterTests` scans the PAF IL and fails on the bare form or on a specification overriding `IgnoreQueryFilters`.
- Statistics (RF07, E0): `GET api/v1/paf/estatistica` (`Estatisticas.View`; type 4 also `Estatisticas.ViewPorAtendente`, else 403) reads the caller's effective scope, never the current unit. Every `unidades`, `filas` or `prioridades` id outside the scope is 403, unknown is 400, and a fila/prioridade outside the asked `unidades` is 400: a filter is never narrowed silently. Each type is an `IConsultaEstatistica` registered in `PafModule` (E1 types 1-6, E2 7-8, E3 9-10); an unregistered type answers an empty table.
- Demo data: `Data/PafDemoSeeder`, called by the DbMigrator `seed-demo` verb only, never by tenant provisioning.

## Station credential (`Estacoes/`, `Conferencia/`, `Autorizacao/`)

- Claims in `Contracts/Authorization/PafClaims` (`paf_papel`, `paf_estacao`, `paf_unidade`, `paf_vinculo`, plus the kit's `tenant`, `sub`, `jti`); role values in `PafPapeisEstacao` (`Emissao`, `Painel`). Single definition: never redeclare claim names elsewhere.
- `ConferenciaRequisicaoMiddleware` runs for every authenticated request of the host: 403 when the `tenant` header or `?tenant=` differs from the token's tenant claim (root operators exempt, stations never); for a station token it checks the live `VinculoEstacao` and the active `Estacao`, sets the unit, and marks `HttpContext.Items["paf:estacao-conferida"]`, which `EstacaoAuthorizationHandler` reads for policies `PafEstacaoEmissao` / `PafEstacaoPainel`.

## Realtime (`TempoReal/`)

- `PafHub` at `/api/v1/paf/hub` (`PafHubRota.Caminho`), policy `PafHub`, groups `PafGrupos` (`paf:{tenant}:unidade:{guid}` and siblings). Writes go through `AvisosTempoReal.GravarAsync` inside the transaction and `EnviarAsync` after commit; the outbox stores the full type name of the `*Paf` events, so renaming one orphans stored rows.
- `PafHubFilter` revalidates on connect and on every client call (live `VinculoEstacao` through `Conferencia/CredencialEstacao`, active kit session through `ISessionService`), aborts on refusal, and installs the token's tenant in the hub scope. Registered with `AddSignalR().AddHubOptions<PafHub>`: a bare `Configure<HubOptions<PafHub>>` is silently ignored (SignalR uses per-hub options only when `HubOptionsSetup<PafHub>` marked them set). Test clients make one `EntrarNoGuiche` round trip after `StartAsync` (`PafOperacao.ProntaAsync`), because the handshake returns before the groups are joined: resolve `PafDbContext` lazily inside the hub, never by constructor.
- `PafHubFilter` also judges an impersonation connection, on connect and on every call, by `act_tenant` = root and `IImpersonationGrantService.IsRevokedOrEndedAsync(jti)` (5 s limit): a revoked or ended grant aborts the connection on its next call, which over WebSockets is the only check after the upgrade.
- `ConexoesPaf` is the connection registry (local list for `Abort` plus `RegistroConexoes` in Valkey, see below). A person connection joins the guichê group of its session's active `SessaoEstacao` on connect; the guichê screen invokes `EntrarNoGuiche` (`PafHubChamadas`) after selecting and after every reconnect. Hooks, called after the write is committed: `EncerrarSessaoAsync` from `RevogacaoSessao`, `EndSessao` (logout), the login's single session (previous sessions) and the refresh refused for licence; `EncerrarEstacaoAsync` from `RevogarVinculo`, `GerarVinculo` (device replaced) and `DisableEstacao`. `MoverSessaoParaGuicheAsync` from `SetGuiche` (the new guichê, and null for a dead occupant it released).
- `RegistroConexoes` (Valkey, keys `paf:{t}:conexoes:{sessao|concessao|estacao}:…` as ZSETs scored by expiry, `paf:{t}:conexao:{id}:grupos|guiche`, global `paf:sessoes-caidas`) reaches the connections of every instance: hooks and `RemoverDeTodosOsGruposAsync` (by session, by grant `jti`) leave groups through `IHubContext.Groups` (crosses the backplane); only the holding instance aborts. Every group join goes through `ConexoesPaf.EntrarNoGrupoAsync`, so the groups are recorded. Valkey down or absent (the test host): local list only, 500 ms ceiling per call. Person and impersonation join `paf:{t}:unidade:{u}` (person: `EstadoSessao`, else the licence unit; impersonation: the grant's own unit from `UnidadeDaConcessao`, never the user group).
- `RenovacaoPelaConexao` (hosted, per instance, step = min(interval, grace)/2): renews the registry entries it holds (validity 2 × interval), renews the live `AtividadeSessao` mark of each session with a connection here (PostgreSQL, also without Valkey; only a live mark, spaced by the interval) and, on each renewed mark, its `ConjuntoLicencas` member in the unit of the row and on each write checks `UserSession` and user active; releases licence and guichê (`Licencas.LiberarAsync`) of a session whose last connection dropped longer than the grace ago, on any instance, only with Valkey. Options `PAF:Sessao` (`CarenciaReconexao` 2 min, `PrazoMarca` 10 min, `IntervaloRenovacao` 1 min) validated on start.
- Renewal hardening (review of wave 0): `RenovacaoPelaConexao` isolates each tenant and each drop (a tenant whose database fails is logged and skipped, the others and the grace release go on); `Licencas.RestaurarMembroAsync` (used by both renewals) rereads the `AtividadeSessao` row after restoring the member and releases it if the row is gone, so a logout or release racing the renewal leaves no ghost member. Tests: `PafRegistroConexoesTests.TenantComBancoFora_*`, `PafConjuntoLicencasTests.RestauracaoQueChegaDepoisDoLogout_*`.
- Every front client connects WebSockets-only with `skipNegotiation: true` (seção 11, 17/10/2026) and invokes nothing while not Connected. The .NET test clients stay on long polling (TestServer closes a WebSocket before the handshake).
- Real WebSocket E2E (O16): `src/Tests/PAF.Kestrel.Tests`, its own process with the host on Kestrel (`WebApplicationFactory.UseKestrel`, one host per process) and the front's client setup (WebSockets only, `SkipNegotiation`, `?tenant=` and `?access_token=`, upgrade status recorded): painel gets `SenhaChamada`, another client's `?tenant` gets 403 at the upgrade, the one-minute token (`JwtOptions:AccessTokenMinutes` = 1 there) is closed at `exp` and the reconnect renews through the secret, a revoked session survives until its next call and is then aborted for good (no automatic reconnect; the new upgrade gets 401). Not in the `Integration.Tests` filter: run the project itself.

## Session and licence (`Sessao/`)

- The access token carries the kit session id in claim `sid` (edit in the Identity token handlers, ADR 0008). The JwtBearer inbound map keeps it as `sid`.
- `GenerateTokenLicenseBehavior` / `RefreshTokenLicenseBehavior` are closed Mediator behaviors (confirmed applied by `PafSessaoLicencaTests`). Root tenant and users with no `UsuarioUnidade` pass straight through: no licence, no single session.
- First slice: no cascade, the principal unit (lowest `Ordem`) pays; the licence does not migrate on unit switch. The seat count is always `AtividadeSessao` rows fresher than 10 min, under `pg_advisory_xact_lock` of the unit.
- Licence set (S09, supersedes the count rule above outside the degraded mode): `ConjuntoLicencas` keeps one Valkey ZSET per tenant and unit (`paf:{t}:licencas:{u}`, score = expiry in the Valkey clock, `TIME` inside the script) plus the index `paf:{t}:sessao:{s}:licenca`. One Lua script releases the given members, returns the unit the session already holds (idempotent per session) or occupies the first candidate with balance, the caller's other sessions counting as free. `Licencas.ReservarAsync` takes a per-user advisory lock (login and refresh of the same user serialize, sessão única), reserves a provisional `reserva:{guid}` member (`PrazoReserva` 1 min), and `ReservaLicenca.ConfirmarAsync` swaps it for the session and the user's earlier sessions in one script, then writes `AtividadeSessao` (still the source of truth; the seat goes back if the commit fails).
- Degraded mode: Valkey not registered, disconnected, past the 500 ms deadline (connection and timeout errors only; a server error propagates), or the rebuild mark `paf:licencas:reconstruido` missing → the unit advisory lock and the `AtividadeSessao` count decide, as in the first slice. `RenovarMarcaAsync` also puts the member back in the unit of the PostgreSQL row (no cascade); `LiberarAsync` removes it. `ReconstrucaoLicencas` (hosted, every instance) rebuilds from fresh rows with an active kit `UserSession` on start, on `ConnectionRestored` and when the mark disappears; members untouched since the snapshot and not in PostgreSQL leave, newer ones and reservations stay; a tenant whose database fails is logged and skipped (its members return on renewal), never holding the global mark. Tests: `PAF.Tests/ConjuntoLicencasTests` (fixture `ValkeyPaf`, pausable and flushable), `Integration.Tests/Tests/PAF/PafConjuntoLicencasTests`.
- Licence cascade (S05, supersedes "no cascade, the principal pays" above): `Licencas.ReservarAsync` takes the candidates from `EscopoUsuario.EscopoEfetivoAsync` in scope order, keeps the ACTIVE ones with a valid `ContratoUnidade` and hands the ordered list to the set script (the first with balance, or the first `UltrapassarComAviso` one, wins); the degraded mode locks every candidate (`paf-licenca:{t}:{u}`) in id order before counting. Refusal messages by cause: no active unit, no active unit with contract, every candidate full. Login and refresh share it. Tests: `PafCascataLicencaTests` (every case with Valkey and degraded), `PafCascataRenovacaoTests` (host).
- Refresh (S05, L28 fixed): `RefreshTokenLicenseBehavior` validates the refresh token (`IIdentityService.ValidateRefreshTokenAsync`), finds the session by the kit digest of the refresh token (first 8 bytes of SHA-256, hex, as `RefreshTokenCommandHandler`) and, only for a session without a live mark, reserves BEFORE the kit handler rotates. A refusal is a 403 with no rotation and no revocation: the old refresh token revives the session once a seat frees. Revived in another unit than the one the screen had (`EstadoSessao`, else the expired row): the Valkey unit state is dropped and `UnidadeCorrenteAlteradaPaf` (method `UnidadeCorrenteAlterada.Metodo`, user group, outbox + direct) tells every window, which re-reads its context (`clients/dashboard/src/features/paf/unidade-corrente.ts`, wired in `guiche/hub-guiche.ts`; every reconnection re-reads too, because the window's own connection dies with the expired mark and the notice usually lands by the outbox copy after it reconnects). Open connections stay in the old unit group until S07 moves them.
- `SessionCheckMiddleware` (module middleware) checks `sid` → active `UserSession` → fresh `AtividadeSessao`, fills `SessaoCorrente` and `IUnidadeCorrente` (Valkey state via `EstadoSessao`, else the licence unit), and renews the mark at most once a minute. The current unit must be in the user's effective scope (`EscopoUsuario`), else the session is revoked (RF08); a disabled unit is NOT checked (open sessions run until they end). Each renewal also checks the user is active (`IUserProfileService`), revoking otherwise. Root tokens get the `UserSession` check too (read in a root-tenant scope when the request targets a client tenant), never the licence. Tokens with `act_sub` or `paf_papel` (`PafClaims.Papel`, same test as `ConferenciaRequisicaoMiddleware`) are not handled here, except for the impersonation barrier below.
- Impersonation barrier (`Sessao/ImpersonacaoPaf`, RF22/RNF15): only the Codefi's impersonation (`act_tenant` = root tenant) operates the PAF. `SessionCheckMiddleware` answers 403 to any other `act_sub` token (missing `act_tenant` included) on every path under `/api/v{n}/paf` (path test, case-insensitive, hub included), before authorization; kit routes keep accepting the client admin's impersonation. Beyond the barrier, an `act_sub` token on a PAF route gets the grant's own branch (S10B): `ConcessaoCorrente` (grant id = token `jti`), no `SessaoCorrente`, no licence, no `AtividadeSessao` row, and the single-session rule never reaches it. `UnidadeDaConcessao` sets `IUnidadeCorrente` from Valkey key `paf:{t}:concessao:{jti:N}:unidade` (TTL = token `exp`); missing or out of the impersonated user's scope, it recreates it by the station of the grant's active `SessaoEstacao`, else the current unit of the user's freshest live session, else the principal (same order from PostgreSQL without Valkey). `X-Paf-Unidade` is ignored for `act_sub`. `SetUnidadeCorrente` under a grant switches only that key (scope and active checks as the session, releases the grant's guichê link, 503 without Valkey) and never touches the user's session or tabs.
- `AtoImpersonacao` (S11A, D28): every PAF write under the Codefi's impersonation records one row (operator `act_sub`, grant `jti`, current unit, atendimento when any) in the write's own transaction; no `act_sub`, no row. Cadastro commands carry the marker `Contracts/v1/IEscritaDeCadastro`, and `Sessao/AtoImpersonacaoBehavior` (constrained open generic) notes the act before the handler, so the handler's `SaveChanges` writes it; a marked handler that writes around the context (`ExecuteUpdate`, raw SQL) calls `AtosImpersonacao.GravarAsync` inside its transaction (as `RevogarVinculo`), and a tracker clear re-notes with `Anotar` (as `GerarVinculo`), else the behavior throws. `Architecture.Tests/PafAtoImpersonacaoMatrizTests` fails any write command (`IBaseCommand` in the PAF assemblies) neither marked nor in its exclusion list with a reason; only S11 empties the guichê exclusions. Unit-scoped: an impersonated write with no current unit gets 403.
- PAF-born revocation goes through `RevogacaoSessao` (release licence and guichê, drop the Valkey state, revoke the `UserSession`). `SetUsuarioUnidades` uses it for every live session whose current unit was taken out. `CreateUnidade` does NOT add the creator to the new unit's scope.
- Effective scope (RF08, ADR 0006, C01): `EscopoUsuario.EscopoEfetivoAsync(usuarioId)` is the single definition, read by both middlewares, `SetUnidadeCorrente`, `ListUnidades` (and `guiche/unidades`, which drops inactive ones), `ListFilasConsolidadas`, `Get/SetUsuarioUnidades` and `ExigirAsync`; never query `UsuariosUnidade` for a scope decision. List scope = the `UsuarioUnidade` rows by `Ordem`. Escopo empresa (`paf.PerfisUsuario.EscopoEmpresa`; no row = list scope) = its single principal row, then every unidade of the tenant by `CriadoEm`, created-later and inactive ones included (the licence cascade skips inactive ones). No principal row = empty scope (fail-closed). `PerfisUsuario` (PK `UsuarioId`, tenant only) also holds `Funcao` (free-text job title, D15) and `Ramal`, edited by C12.
- Scope grants (`UsuariosUnidade` GET/PUT, body `EscopoEmpresa`): the tenant admin (`EscopoUsuario.AdministraTenantAsync` = escopo empresa profile OR holder of `Unidades.Create`, the latter kept by the decision of 17/10/2026 until RF23 seeds the first escopo empresa) reads and edits any user, grants any ACTIVE unidade of the tenant (else 400) and grants escopo empresa; anyone else gets 403 for escopo empresa and keeps the RF08 subset rule on the effective scope (grant only inside his scope, touch only users whose scope fits in it, never an escopo empresa user). Escopo empresa carries exactly one unidade, the principal (400). `SetUsuarioUnidades` serializes per user with `pg_advisory_xact_lock(hashtextextended('paf-escopo:{tenant}:{usuario}'))` and revokes on the effective-scope delta after commit.
- Unidades cadastro (RF23, C02): create, disable and enable need `EscopoUsuario.AdministraUnidadesAsync` (escopo empresa profile AND a principal row; holding `Unidades.Create` is not enough, unlike `AdministraTenantAsync`), 403 `MensagemSoAdministradorDaEmpresa`; update needs the unidade in the effective scope. `GET unidades/administracao` returns that same rule for the screen buttons. `ListUnidades` carries the contract in force (`ContratoVigenteResumoDto`, same validity as the licence, latest start wins), a third explicit cross-unit path (`IgnoreQueryFilters([PafQueryFilters.Unidade])` on `ContratosUnidade`). Disabling revokes no session; emission then answers 409. Tests: `PafCadastroUnidadesTests`. Test setups insert unidades straight in the database (`PafApi.CriarUnidadeAsync`, `InserirUnidadeAsync`).
- `UX_UsuariosUnidade_Ordem` (UsuarioId, Ordem, TenantId) is a `DEFERRABLE INITIALLY DEFERRED` unique constraint created by raw SQL in migration `EscopoEmpresaPerfisUsuario` and absent from the EF model (as a model index EF refuses a position swap): a duplicated principal fails at COMMIT, not at the INSERT.
- Routes under `api/v1/paf/sessao`: `unidade-corrente`, `guiche` (`Permissions.PAF.Guiches.Selecionar`), `logout`.

## Operational flow (`Features/v1/Fichas`, `Features/v1/Atendimentos`, `Features/v1/Painel`)

- Emission: `POST api/v1/paf/estacao/emissao/fichas` (policy `PafEstacaoEmissao`, header `Idempotency-Key` required, kit `WithIdempotency` in front). Number = day max + 1 (or `NumeroInicial`), day and window from the PostgreSQL clock; `UX_Fichas_Numeracao` retries in a new transaction (max 10, logged); `UX_Fichas_ChaveIdempotencia` returns the stored ficha.
- Guichê (`Permissions.PAF.Atendimentos.Operar`, basic; guichê from the session's `SessaoEstacao`): `POST api/v1/paf/guiche/chamar-proximo`, `POST api/v1/paf/guiche/atendimentos/{id}/{rechamar|iniciar|encerrar|cancelar}`. Call = candidate `FOR UPDATE OF a SKIP LOCKED`, then all rows of the ficha `FOR UPDATE SKIP LOCKED` in id order (savepoint rollback on skip); other operations lock the ficha rows waiting, in id order, and re-validate. Every state UPDATE stamps `now()` and increments `Versao`. Option "respeitar ordem das filas" = key `respeitarOrdemFilas` in `Estacao.Configuracao` (ponytail).
- Guichê link lock: the call and every release of a session's guichê (switch, unit change) take `SELECT ... FOR UPDATE` on the session's `SessoesEstacao` row inside their transaction (`VinculosGuiche.TravarAtivoDaSessaoAsync`, `SoltarSemAtendimentoEmCursoAsync`), so no guichê is released with an atendimento `Chamado` on it. Both throw without an open transaction.
- Ficha lock (`OperacaoGuiche.TravarFichaAsync`, F01): every state change outside the chamar-próximo selection enters here, with or without a guichê. Unit-filtered read of the `FichaId` (other unit = 404), then all rows of the ficha `FOR UPDATE ORDER BY "Id"` (never the target row first: entering by different rows would deadlock), then the target re-read; throws `InvalidOperationException` without an open transaction. `TravarAsync` is the guichê wrapper (404 before locking when the atendimento is not on this guichê). `SoltarVinculoDeEstacaoInativaAsync` releases the link of a deactivated station in the caller's transaction; guichê encerrar and cancelar call it, and every later path that ends an atendimento on a station calls it too, never a copy.
- Guichê screen reads (`Permissions.PAF.Guiches.Selecionar`, basic, no cadastro permission): `GET api/v1/paf/guiche/unidades` (only `Id` and `Nome` of the ACTIVE unidades of the caller's scope), `guiches` (active guichês of the current unit, with the occupant's user name and the senha of another user's pendência), `posto` (current unit, selected guichê, the caller's own atendimento in progress, never another user's).
- Pendência on selection (seção 5, RF04): an atendimento `Chamado`/`EmAtendimento` left on the guichê by a released link. Its own user resumes it by selecting the guichê again; another user gets 409 unless `SetGuicheCommand.LiberarPendencia`, which cancels it (RF12, `Chamado` or `EmAtendimento`) in the selection's transaction, under the ficha lock, with `AtendimentoAtualizadoPaf` after commit.
- RF12 cancel outside the guichê (F04): `POST api/v1/paf/fichas/atendimentos/{id}/cancelar` (`FichasDoDia.Cancelar`, not basic; the guichê's own cancel stays under `Atendimentos.Operar`). Single service `OperacaoGuiche.CancelarAsync` (locks the ficha) / `CancelarTravadoAsync` (caller already holds the lock): Aguardando, Chamado or EmAtendimento → Cancelado with `Versao+1`, else 409 `MensagemNaoCancelavel`; only Chamado/EmAtendimento release the waiting siblings; a deactivated station's link is released in the same transaction. Returns `AtendimentoAtualizadoPaf` plus one `FilaAtualizadaPaf` per touched fila, written by `ConfirmarEAvisarTodosAsync` before the commit and sent after it. The pendência cancel of `SetGuiche` calls this service; F07, F14, C05 and C12 call it too, never a copy. Tests: `Integration.Tests/Tests/PAF/PafCancelamentoFichaTests`.
- Reabilitar (RF12, F05; `Permissions.PAF.FichasDoDia.Reabilitar`, no guichê): `POST api/v1/paf/fichas/atendimentos/{id}/reabilitar`. Under the ficha lock: only `Cancelado`; with `somenteFichasDaDataAtual` on, `DataElegibilidade` BEFORE the rewrite must be today (SP, database clock), else 409 "emita ficha nova"; 409 naming the guichê when a sibling is `Chamado`/`EmAtendimento`. One UPDATE ends the eligibility cycle: `Aguardando`, `ElegivelDesde = now()`, `ChamadoEm`/`UltimaRechamadaEm`/`IniciadoEm`/`CanceladoEm`/`EstacaoId`/`UsuarioId` NULL, `Versao + 1`; `CriadoEm`, `DataOperacional` and `Rechamada` rows untouched (place in the queue comes from creation). Notices: `AtendimentoAtualizadoPaf` (`Aguardando`) and `FilaAtualizadaPaf`; the painel reducer drops the entry on `Aguardando` with a higher `Versao`.
- Station configuration (`GET api/v1/paf/estacao/{emissao|painel}/configuracao`) carries `Botoes`: filas of the emission role × prioridades, fila and prioridade active, covered and inside the time window (next line), ordered by station then fila order; empty for the painel.
- Guichê coverage (RF02, C07): `Features/v1/Filas/CoberturaGuiche` is the single definition: a (fila, prioridade) pair is covered while an ACTIVE station lists the fila in its `Guiche` role and enables the prioridade (emission and painel lists never count; who is logged in does not matter). Buttons also need the unidade active and the fila window open by the PostgreSQL clock (`Fila.JanelaPermiteEmissao`); the emission refuses an uncovered pair with 409. Emission checks under `pg_advisory_xact_lock_shared` and `Update/DisableEstacao` hold the exclusive one (key `paf-cobertura:{tenant}:{unidade}`), so no emission passes after a commit that removed the last guichê; both return the pairs the write left uncovered, and `ListFilas` carries `CombinacoesSemCobertura`. The totem re-reads its buttons on `FilaAtualizada` and every 60 s (ponytail: window edges push no notice).
- Painel state: `GET api/v1/paf/estacao/painel/estado` (policy `PafEstacaoPainel`): today's calls of the painel's filas, latest call or recall first, with `Versao`.
- Notices: emission → `FilaAtualizadaPaf`; call → `SenhaChamadaPaf` (guichê + active painéis listing the fila) and `FilaAtualizadaPaf`; recall → `SenhaRechamadaPaf`; start/close/cancel → `AtendimentoAtualizadoPaf`. Always `GravarAsync` before commit, `EnviarAsync` after.
- Forwarding (RF17, F08; `Permissions.PAF.Atendimentos.Encaminhar`, basic): `GET api/v1/paf/guiche/encaminhamento/destinos` (the guichê's `EmAtendimento`, active filas of the unit minus the origin, `ForaDoHorario` by the PostgreSQL clock, prioridades active AND covered by `CoberturaGuiche`) and `POST api/v1/paf/guiche/atendimentos/{id}/encaminhar {filaIds, prioridadeId}`. Lock order: coverage lock shared (before any row lock, as `DisableEstacao` takes it first), then the session link, then the ficha; under the locks it re-validates `EmAtendimento` on this guichê, destinations (active, this unit, not the origin; the window is not checked, forwarding is not emission) and the prioridade (active, covered in every destination, else 409). Origin `Encerrado` with `Versao+1`, waiting siblings released, one `Aguardando` per destination with `AtendimentoOrigemId`, same ficha, no new number; inactive station link released by the F01 helper. Notices: origin `AtendimentoAtualizadoPaf` plus one `FilaAtualizadaPaf` per destination. Tests: `Integration.Tests/Tests/PAF/PafEncaminhamentoTests`.
- Raw SQL skips global filters: every raw statement carries `"TenantId"` (and `"UnidadeId"` where it selects).
- Station configuration blocks (C04, `Features/v1/Estacoes/ConfiguracaoDaEstacao`): Create/Update take `Ramal` (`Estacoes.Ramal`, max 20) and `BlocosEstacaoDto` (`Emissao`, `Guiche`, `Painel`), one block exactly per papel of the type (else 400), unknown JSON members 400 (`JsonUnmappedMemberHandling.Disallow`). Rules: times 1..600 s; colors `#RRGGBB`, all of a block or none, each text vs the block background >= 4.5:1 unrounded (`Aparencia/Contraste`, shared with the fila appearance); totem button >= 44 px; totem font >= parameter `fonteMinimaTotemPx` (D17, default 24). Stored jsonb keeps the operational keys at the ROOT (`respeitarOrdemFilas`, `selecionarFicha`, `tempoExibicaoChamadaSegundos`, `prazoCicloEmissaoSegundos`, read by the call and the screens) and the rest under `emissao`/`guiche`/`painel`. Update locks the station row `FOR UPDATE` after the coverage lock. `SenhaChamada`/`SenhaRechamada` (init properties) and `ChamadaPainelDto` carry `NumeroGuiche` and `NomeExibicaoGuiche` (null for a station never saved through the cadastro). Screen: `/paf/estacoes`.

- Fila cadastro (RF02, C09): `Create/UpdateFila` carry `SetorId` (null = "Sem setor") and `Aparencia` (`Fonte`, `CorFonte`, `CorBotaoSelecionado`); each grid line carries `CorBotao`. Colors are `#RRGGBB` only, null = the station's default. Contrast floor (RNF19) is `Aparencia/Contraste` (single definition, shared with the station blocks of C04; front mirror `features/paf/aparencia/contraste.ts`): every button color (selected fila, each prioridade) against `CorFonte` >= 4.5:1, and a button color without `CorFonte` is 400. The pair spans fila and grid, so `Features/v1/Filas/AparenciaDaFila` checks it in the four write handlers against the committed other side (ponytail: no row lock). Setor (`api/v1/paf/setores`, fila permissions, decided 24/08/2026: kept inside the fila cadastro): create, rename, list in the current unit, never deleted; homonym 409 (friendly check, then `UX_Setores_Nome`); a setor of another unit is 404. The totem buttons carry the fila's font and colors and the line's `CorBotao`; the totem screen applies them in C18. Screen: `/paf/filas`.

## Media storage (`Midias/`, M02, ADR 0007)

- Bytes go through the kit's `IStorageService` (`BuildingBlocks/Storage`, provider by `Storage:Provider`), never the Files module (key without unit, its own permission, purge jobs that would delete objects under the 30-day lock). The PAF only composes the key and checks the unit.
- Key: `ChaveObjetoMidia.NovoEnvio(tenantId, unidadeId, formato)` → `paf-midia/{tenantId}/{unidadeId}/{envioId:N}.{ext}`, a new v7 id per upload (never reused, so a swap never overwrites), outside `public/`. The uploaded name never enters it: the extension comes from the table, and a tenant id outside `[A-Za-z0-9][A-Za-z0-9_-]{0,63}` throws. Pass `envio.Chave` to the storage as is: the kit's S3 provider prepends `Storage:S3:Prefix` itself (`app` → `app/paf-midia/...`).
- `FormatosMidia.Aceitos` is the single RF03 table (extension, `TipoMidia`, MIME as ASP.NET Core maps it); `PorNomeDeArquivo` matches the last extension case-insensitively (`.MP4` → `.mp4`) or returns null.
- Options `PAF:Midia` (`OpcoesMidia`, validated on start): `ValidadeUrlEnvio` 15 min (≤ 7 days, the R2 cap), `TetoVideoBytes` 500 MiB, `TetoImagemBytes` 20 MiB, `TetoAudioBytes` 50 MiB, `MargemLeitura` 10 min. Start also fails when `Storage:S3:Prefix` is under `public/` or is a text prefix of `paf-midia` (the kit's `NormalizeKey` skips prefixing a key that already starts with the prefix text).
- RustFS proof: `Integration.Tests/Tests/PAF/PafMidiaArmazenamentoTests` (presigned PUT, final key read with the raw S3 client, signed GET 200, unsigned GET 403 next to a `public/*` control 200).
- ADR citation check: `node src/Modules/PAF/ferramentas/citacoes-adr.mjs <repo> src/Modules/PAF/ferramentas/citacoes-adr.json <adr-0007.md> <adr-0008.md>`; every backticked `arquivo:linha` (and the `:N` continuation) needs a manifest entry whose symbol is in the cited lines at the entry's revision (`HEAD`, or `a9675375` where the ADR describes the kit before the PAF edited it). Run it after any edit to a cited kit file or to the ADRs; a renumbered citation is a manifest edit in the same commit.

## Degraded mode without Valkey (S14, `Saude/`)

- `GET api/v1/paf/saude` (anonymous, no rate limit) runs only the checks tagged `paf`: `db:paf` (own `NpgsqlConnection`, no pool, `Timeout`/`Command Timeout` 1 s: a pooled connection returned at scope disposal held the probe until the server came back) and `valkey:paf` (`ConjuntoLicencas.ReconstruidoAsync`, 500 ms; Valkey down or set not rebuilt = `Degraded`, no Valkey configured = `Healthy`). 200 for `Healthy`/`Degraded`, 503 only for `Unhealthy` (PostgreSQL). The kit's `/health/ready` stays 503 without Valkey by design (its `redis` check); deploy and balancer probe `paf/saude`. Body: name, status and our fixed description, never the exception.
- Valkey connection string prazos the environments must use (O02): `connectTimeout=2000,syncTimeout=500,asyncTimeout=500,abortConnect=false` (`PafHostValkey.PrazosValkey`). With the Valkey stalled every kit call costs that plus up to the client's 1 s heartbeat; measured with it paused: guichê p95 ~2 s, emission ~5 s (kit idempotency filter, four calls), impersonation with a cold grant cache ~3.5 s.
- `CacheDeTenantSemValkey` wraps the kit's `OnTenantResolveCompleted` (PostConfigure, no kit file edited): the kit copies the tenant into the Finbuckle distributed cache store with no error handling, so without Valkey every request died in 500 before reaching the PAF. The copy waits 100 ms and goes on in the background; failures are logged. Ponytail: remove when the kit guards that write (upstream).
- `AvisosTempoReal.EnviarAsync` waits 100 ms for the fast path (the backplane publish ignores the token); past that the send goes on in the background, a late failure is logged, and the outbox delivers.
- `Licencas.ReservarAsync`, when the occupation does not answer, queues a fire-and-forget release of the provisional member (`ConjuntoLicencas.SoltarOcupacaoSemResposta`): a stalled Valkey runs the pending script when it returns and would hold a ghost reservation for `PrazoReserva`.
- Return of a stalled Valkey: the client drops the connection on the first timeouts, so `ConnectionRestored` triggers `ReconstrucaoLicencas`.
- Harness: `Integration.Tests/Tests/PAF/PafHostValkey` is a second API host with its own PostgreSQL and Valkey, both pausable, collection `PafHostValkey` with `DisableParallelization` (it sets `CachingOptions__Redis` as an env var during the host build, because the kit reads it eagerly, and resets the static `ModuleLoader`). Tests: `PafModoDegradadoTests`.

## Tenant creation (`Provisionamento/`, RF23, D18, C03)

- `TenantCriadoPafHandler` (`IIntegrationEventHandler<TenantSubscribedIntegrationEvent>`, picked up by the existing `AddIntegrationEventHandlers` in `PafModule`) writes the initial unidade (`Unidade.Inicial`, name = tenant name, no contract: no login until Codefi writes one, C08) and enqueues `AssociacaoAdministradorInicial`. The job finds the admin by the tenant's `AdminEmail`, seeds the roles, and gives him escopo empresa with the initial unidade at `Ordem` 0 only when he has no scope yet (lock `paf-escopo:{tenant}:{usuario}`, same as `SetUsuarioUnidades`); admin not seeded yet → reschedules every 30 s up to `Teto` (20), then warns and stops.
- `UX_Unidades_Inicial` (Unidades: Inicial, TenantId WHERE "Inicial"): one initial unidade per tenant; concurrent deliveries lose the race on it and read the winner's row. The event bus installs only the tenant id, so handler and job open their own scope with the full tenant (`ProvisionamentoTenantPaf.AbrirEscopo`, synchronous because the Finbuckle context is an AsyncLocal).
- `PapeisPadrao`: kit roles Administrador, Gerente, Atendente with PAF permissions only (no kit permission, no `Permissions.Users.Update`), created through `IRoleService` when missing; an existing role keeps its permissions. Administrador lacks `Unidades.Create/Update` and `Parametros.UpdateEmpresa` (company admin only); `Estatisticas.ViewPorAtendente` (D10) waits for its `IsRoot` flag to flip. `PafDemoSeeder` marks its unidade `Inicial` and seeds the same roles; on a database seeded before the column it adopts the existing "Loja Demo" (`Unidade.MarcarComoInicial`) instead of adding a second one. Wave-0 tenants with real unidades stay without an initial one, so the C03 login refusal does not reach them (no backfill).
- `GenerateTokenLicenseBehavior` refuses (403, `MensagemSemUnidade`) a client-tenant login with no `UsuarioUnidade` once the PAF has reached the tenant (`Licencas.PafProvisionadoAsync`: initial unidade exists); before that the kit login stands, because the event waits for the outbox (off in the integration host) and the kit's tests log in right after provisioning. The refresh and the per-request check keep passing such a user through.

## Media schema (`Domain/EnvioMidia`, `Midia`, `ProgramacaoMidia`, `PainelMidia`; `Data/Configurations/MidiaConfigurations.cs`)

- Four unit-scoped tables (`IEscopoUnidade`, no soft delete): `EnviosMidia` (one upload; source of the object key, never reused, RF03; `CriadoEm`/`ConfirmadoEm`/`RecusadoEm`/`RemovidoEm` stamped by PostgreSQL, so confirm, refuse and cleanup are raw `now()` UPDATEs), `Midias` (`EnvioId` + copy of `ChaveObjeto`, `Versao`, `Ativa`), `ProgramacoesMidia` (BRT wall-clock dates and `HoraInicial`, `Repeticoes`, `Dias` = `DiasSemana` bit mask in `DayOfWeek` order, 127 = every day; media time, total and end hour are computed on read, never stored), `PainelMidias` (own `Id`, `Ordem`; the same mídia may repeat in a list).
- `Midia.Criar(envio, …)` takes unidade, tipo, envio and key from the `EnvioMidia`. Midnight crossing and overlap (D13) depend on the mídia duration and are validated by the writer, not by a CHECK.
- Same-unit composite FKs: `FK_Midias_EnviosMidia_MesmaUnidade` (UnidadeId, EnvioId, ChaveObjeto), `FK_ProgramacoesMidia_Midias_MesmaUnidade`, `FK_PainelMidias_Midias_MesmaUnidade` (UnidadeId, MidiaId), `FK_PainelMidias_Estacoes_MesmaUnidade` (UnidadeId, EstacaoId), against the alternate keys `AK_EnviosMidia_UnidadeId_Id_ChaveObjeto`, `AK_Midias_UnidadeId_Id`, `AK_Estacoes_UnidadeId_Id` (declared from the dependent side). Every principal key includes `Id`: a key on (UnidadeId, ChaveObjeto) alone would be created before `UX_EnviosMidia_ChaveObjeto` and be the constraint PostgreSQL names for a duplicated key.

| `UX_EnviosMidia_ChaveObjeto` | EnviosMidia | ChaveObjeto, TenantId |

## Media cadastro (`Features/v1/Midias`, M03, RF03)

- Routes under `api/v1/paf/midias`: `POST envios` (`Midias.Create`) and `POST {id}/envios` (`Midias.Update`, same type as the mídia) return the presigned PUT (`EnvioMidiaDto`: `Url`, `CabecalhosObrigatorios` to send verbatim, `ExpiraEm`, `TetoBytes`); `POST` (create = confirm), `PUT {id}` (description, duration), `PUT {id}/arquivo` (swap), `POST {id}/enable|disable`, `GET`. No deletion. Edit and swap carry the `Versao` read; every write takes `FOR UPDATE` on the mídia row (`MidiaTravada`) and answers 409 on a stale version; enable and disable also raise `Versao`.
- Request: the last extension of `NomeArquivo` picks the format (`FormatosMidia`, so `x.mp4.avi` is refused and `x.avi.mp4` is an mp4), `ContentType` must be that format's MIME (parameters ignored), else 400 with the list. The name is never stored nor logged; the key is `ChaveObjetoMidia` with the current unidade. The `EnvioMidia` row is written before the URL is signed.
- Confirmation (`ConfirmacaoEnvioMidia`, create and swap): HEAD outside any transaction; no object = 409, nothing written (the kit's S3 `HeadObjectAsync` also returns null on any store error); stored type, empty file or over `TetoBytes(tipo)` = raw `RecusadoEm = now()` committed on its own (left for M09), then 400. Accepted = raw `ConfirmadoEm = now()` conditional on the envio still open, in the write's transaction: a second confirmation of the same envio waits on that row and returns the mídia already created. A swap loser's envio stays unreferenced; the old object is never removed by the swap.
- Store calls go only through `Midias/ArmazenamentoMidia`, each bounded by `PAF:Midia:PrazoArmazenamento` (5 s, at most 30 s): past it, 503 `MensagemSemResposta`. Ponytail: no first-bytes sniffing, the MIME is the one the signed PUT forced.
- Tests: `Integration.Tests/Tests/PAF/PafMidiaCadastroTests` (RustFS; also `PafMidiaCadastroTenantTests` for 403, other tenant and impersonation acts, `PafMidiaArmazenamentoParadoTests` with a silent TCP store), `PAF.Tests/MidiaCadastroTests`.
